# Getting Help

If you encounter issues or have questions about configuring Tendril, multiple support resources and
diagnostic tools are available.

## Run diagnostics first

Before submitting an issue or asking for help, run Tendril's built-in environment doctor:

```bash
tendril doctor
```

`tendril doctor` verifies the `$TENDRIL_HOME` directory, `config.yaml` syntax, [SQLite](https://www.sqlite.org)
database accessibility, the [plans](../02_Concepts/01_Plans.md) directory, [Git](https://git-scm.com/), and
[GitHub CLI](https://cli.github.com/) authentication.

If a specific plan or job failed, you can bundle full diagnostics using `tendril report-bug`:

```bash
# Package plan state, verification reports, and job logs into a zip
tendril report-bug <plan-id>
```

This generates a diagnostic archive that packages the plan YAML, revision history, verification output,
and raw agent transcripts without exposing sensitive credentials.

## Discord community

The fastest way to reach the development team and other builders is our
[Discord server](https://discord.gg/FHgxkDga3y). Join to ask questions, share feedback, and discuss custom
promptware workflows.

## GitHub issues

Found a bug or want to request a feature? Open an issue on our
[GitHub repository](https://github.com/Ivy-Interactive/Ivy-Tendril-V2/issues).

> [!TIP]
> Always include the output of `tendril doctor` and `tendril version` in your issue description. If
> reporting a failed plan execution, attach the diagnostic zip generated by `tendril report-bug <plan-id>`
> or the job log from `$TENDRIL_HOME/Jobs/`.
