# GitHub

## प्रमाणीकरण (Authentication)

Tendril [GitHub](https://github.com) के साथ प्रमाणीकरण के लिए [GitHub CLI](https://cli.github.com) (`gh`) का उपयोग करता है। GitHub सुविधाओं का उपयोग करने से पहले प्रमाणित करने के लिए `gh auth login` चलाएं।

> [!NOTE]
> सुनिश्चित करें कि `gh` इंस्टॉल है और आपके PATH पर उपलब्ध है। यदि यह अनुपलब्ध है तो ऑनबोर्डिंग के दौरान Tendril आपको संकेत देगा।

## इनबॉक्स के माध्यम से इश्यू इम्पोर्ट करना

Tendril [GitHub](https://github.com) इश्यू ब्राउज़ करने और उन्हें [प्लान](../02_Concepts/01_Plans.md) में बदलने के लिए साइडबार में एक समर्पित **Inbox** दृश्य प्रदान करता है:

1. नेविगेशन साइडबार से **Inbox** खोलें।
2. एक श्रेणी चुनें:
   - **My Issues**: कॉन्फ़िगर किए गए प्रोजेक्ट रिपॉजिटरी में आपको सौंपे गए इश्यू।
   - **Review Requests**: आपकी समीक्षा का अनुरोध करने वाले ओपन पुल रिक्वेस्ट।
   - **Project Issues**: चयनित प्रोजेक्ट रिपॉजिटरी के लिए सभी ओपन इश्यू।
3. खोज शब्दों, लेबल्स या माइलस्टोन्स द्वारा फ़िल्टर करें। एक एकल क्वेरी अधिकतम 1,000 ओपन इश्यू प्राप्त करती है (GitHub की खोज सीमा)।
4. एक या अधिक इश्यू चुनें और `CreatePlan` [promptware](../02_Concepts/02_Promptwares.md) लॉन्च करने के लिए **Create Plan** पर क्लिक करें, या शुरू करने से पहले New Plan डायलॉग में प्लान विवरण को कस्टमाइज़ करें।

प्रत्येक बनाया गया प्लान सीधे मूल GitHub इश्यू से लिंक करने वाले स्रोत URL को बनाए रखता है।

### स्वचालित इश्यू स्वीप और प्रस्ताव

Tendril सौंपे गए GitHub इश्यू के लिए एक स्वचालित बैकग्राउंड स्वीप शामिल करता है:

- Tendril नए सौंपे गए इश्यू के लिए GitHub से कितनी बार पूछताछ करता है, यह सेट करने के लिए `inbox.checkIntervalMinutes` कॉन्फ़िगर करें (या Inbox दृश्य में Settings गियर पर क्लिक करें)।
- **Auto-Accept Mode**: जब `inbox.autoAcceptAssignedIssues` सक्षम होता है, तो नए खोजे गए इश्यू तुरंत एक `CreatePlan` कार्य शुरू करते हैं।
- **Proposals Mode**: अक्षम होने पर, स्वीप किए गए इश्यू Inbox दृश्य में **Inbox Proposals** के रूप में स्टेज किए जाते हैं। आप प्रत्येक प्रस्ताव के विवरण की समीक्षा कर सकते हैं और **Accept** (प्लान शुरू करना) या **Dismiss** (एक स्थायी रिकॉर्ड संग्रहीत करना ताकि इश्यू कभी भी पुनः इम्पोर्ट न हो) चुन सकते हैं।
- निर्धारित टाइमर की प्रतीक्षा किए बिना तत्काल मैनुअल स्वीप ट्रिगर करने के लिए Inbox टूलबार में **Check Now** पर क्लिक करें।

## पुल रिक्वेस्ट बनाना

जब कोई प्लान अपने परिवर्तनों को पूरा और सत्यापित कर लेता है, तो पुल रिक्वेस्ट बनाने के लिए **Create PR** डायलॉग खोलें:

1. जनरेट किए गए PR शीर्षक, विवरण और समीक्षकों की समीक्षा करें और संपादित करें।
2. PR विकल्प कॉन्फ़िगर करें:
   - **Solve Merge Conflicts**: लक्षित बेस के विरुद्ध शाखा मर्ज विरोधों को स्वचालित रूप से हल करने का प्रयास करता है।
   - **Merge**: जाँच पास होने के बाद PR को मर्ज करता है (मर्ज किए बिना टीम समीक्षा के लिए PR खोलने के लिए अनचेक करें)।
   - **Delete Branch**: मर्ज होने के बाद worktree शाखा को हटा देता है।
   - **Include Artifacts**: PR बॉडी में प्लान सत्यापन कलाकृतियाँ (artifacts), स्क्रीनशॉट और लॉग संलग्न करता है।
   - **Create as Draft**: पुल रिक्वेस्ट को ड्राफ्ट स्थिति में खोलता है।
3. Tendril शाखा को पुश करने, पुल रिक्वेस्ट बनाने और PR URL को प्लान से लिंक करने के लिए `gh` के माध्यम से `CreatePr` [promptware](../02_Concepts/02_Promptwares.md) चलाता है।

## PR स्थिति ट्रैकिंग

साइडबार में [Pull Requests दृश्य](../04_Apps/06_PullRequests.md) आपके प्रोजेक्ट्स में सभी ओपन, मर्ज और बंद पुल रिक्वेस्ट को ट्रैक करता है। Tendril PR स्थिति परिवर्तनों पर नज़र रखता है, जिससे आपका [प्लान बोर्ड](../04_Apps/03_Plans.md) बिना किसी मैन्युअल हस्तक्षेप के सिंक रहता है।
