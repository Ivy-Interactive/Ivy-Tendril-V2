# जीवनचक्र और जॉब्स

हर बार जब Tendril आपकी ओर से कुछ करता है, तो यह एक **जॉब (job)** बनाता है: एक [प्लान](01_Plans.md) के विरुद्ध एक एकल
[वर्कफ़्लो एजेंट (प्रॉम्प्टवेयर)](02_Promptwares.md) का एक रन। जॉब्स के माध्यम से ही एक प्लान
अपने जीवनचक्र से होकर गुजरता है, और यही वह चीज़ है जिसे आप डेस्कटॉप ऐप और CLI में रीयल-टाइम में देखते हैं।

## जॉब स्थितियाँ

| स्थिति        | अर्थ                                                                          |
| ------------- | ----------------------------------------------------------------------------- |
| **Pending**   | निर्मित, अभी तक कतार में स्वीकार नहीं किया गया।                               |
| **Queued**    | उपलब्ध समवर्ती स्लॉट (concurrency slot) की प्रतीक्षा में।                     |
| **Running**   | कोडिंग एजेंट प्रक्रिया सक्रिय रूप से निष्पादित हो रही है।                     |
| **Completed** | सफलतापूर्वक समाप्त हुआ और सभी आवश्यक गेट्स पास किए।                           |
| **Failed**    | एजेंट में त्रुटि आई, या आवश्यक सत्यापन जांच विफल हो गईं।                      |
| **Timeout**   | अपनी कॉन्फ़िगर की गई निष्पादन समय सीमा पार कर ली और समाप्त कर दिया गया।       |
| **Stopped**   | उपयोगकर्ता की कार्रवाई द्वारा रोका गया।                                       |
| **Blocked**   | आगे नहीं बढ़ सकता — किसी निर्भर जॉब, क्रेडेंशियल, या निर्णय की प्रतीक्षा में। |

## निष्पादन लूप

1. **Queue** — जॉब बनाई जाती है और वर्तमान में चल रहे कार्यों के पीछे कतारबद्ध की जाती है।
2. **Prepare** — कोड-संशोधित करने वाले प्रॉम्प्टवेअर्स ([ExecutePlan](02_Promptwares.md),
   [RetryPlan](02_Promptwares.md)) के लिए, Tendril प्लान के
   `Worktrees/{repo-name}/` फ़ोल्डर के तहत प्रति रिपॉजिटरी एक पृथक
   [Git worktree](https://git-scm.com/docs/git-worktree) का प्रावधान करता है। रन आपके प्राथमिक कार्यशील चेकआउट को कभी नहीं छूता या लॉक नहीं करता।
3. **Implement** — वर्कफ़्लो एजेंट क्रमिक कमिट करते हुए प्लान के चरणों के माध्यम से काम करता है।
4. **Verify** — प्रत्येक कॉन्फ़िगर किया गया सत्यापन गेट वर्क-ट्री में निष्पादित होता है और अपना परिणाम रिकॉर्ड करता है।
5. **Report** — आउटपुट लॉग, टोकन लागत और अद्यतन प्लान स्थिति डिस्क पर सहेजी जाती है और डेमॉन को
   रिपोर्ट की जाती है।

किसी जॉब को रोकने से प्लान उसी स्थिति में वापस आ जाता है जिसमें वह जॉब शुरू होने से पहले था, जबकि
वर्क-ट्री की स्थिति सुरक्षित रहती है ताकि आप आंशिक प्रगति का निरीक्षण कर सकें। पूरी स्थिति तालिका के लिए [प्लान](01_Plans.md) देखें।

## सत्यापन

सत्यापन `plan.yaml` में दर्ज एक स्वचालित गुणवत्ता गेट है। प्रत्येक जांच एक परिणाम उत्पन्न करती है —
`Pass`, `Fail`, या `Skipped` — साथ ही प्लान के `Verification/` फ़ोल्डर में एक विस्तृत रिपोर्ट भी।
कौन सी जांचें चलेंगी यह इस बात पर निर्भर करता है कि प्लान किन फ़ाइलों को संशोधित करता है:

| सत्यापन         | जांचें                                                                 |
| --------------- | ---------------------------------------------------------------------- |
| **NpmBuild**    | pnpm / npm वर्कस्पेस बिना किसी त्रुटि के बनता है।                      |
| **NpmLint**     | TypeScript / JavaScript पैकेजों पर लिंटिंग और फ़ॉर्मेटिंग पास होती है। |
| **NpmTest**     | स्वचालित परीक्षण सूट पास होते हैं (Vitest, Jest, आदि)।                 |
| **RustBuild**   | Cargo पैकेज कंपाइलर त्रुटियों के बिना संकलित होते हैं।                 |
| **RustClippy**  | Clippy लिंटर कोई चेतावनी या त्रुटि रिपोर्ट नहीं करता।                  |
| **RustFormat**  | `cargo fmt --check` सुसंगत फ़ॉर्मेटिंग की रिपोर्ट करता है।             |
| **RustTest**    | Rust यूनिट और एकीकरण परीक्षण सूट पास होते हैं।                         |
| **Screenshots** | UI संशोधनों के लिए दृश्य प्रमाण कैप्चर किए गए।                         |
| **CheckResult** | एजेंट की स्वयं की एंड-टू-एंड पुष्टि कि प्लान मानदंड मान्य हैं।         |

एक सत्यापन जो किसी प्लान पर लागू नहीं होता है, उसे चुपचाप छोड़ने के बजाय `Skipped` के रूप में चिह्नित किया जाता है,
जिससे एक स्पष्ट ऑडिट ट्रेल सुनिश्चित होता है। एक प्लान **Review** तक तभी पहुँचता है जब उसके आवश्यक सत्यापन पास हो जाते हैं।
यदि कोई सत्यापन विफल हो जाता है, तो प्लान **Failed** में प्रवेश करता है, और
[RetryPlan](02_Promptwares.md) सटीक त्रुटि आउटपुट
और वर्तमान अंतर (diff) को संदर्भ के रूप में लेकर दूसरा प्रयास कर सकता है।

> [!TIP]
> जब कोई सत्यापन विफल हो जाए, तो `Verification/` में रिपोर्ट का निरीक्षण करें और सीधे प्लान के वर्क-ट्री में कमांड का परीक्षण करें।
> जांच आमतौर पर सही होती है और हो सकता है कि वर्क-ट्री में केवल कोई निर्भरता (dependency) या बिल्ड आर्टिफ़ैक्ट गायब हो —
> [कोडबेस को ऑनबोर्ड करना](../01_GettingStarted/03_Onboarding.md) देखें।

## समवर्तीता और वर्क-ट्री

[~/.tendril/config.yaml](../03_Configuration/01_Setup.md) में `maxConcurrentJobs` द्वारा नियंत्रित कई जॉब्स एक साथ चल सकती हैं (डिफ़ॉल्ट `20`):

```yaml
maxConcurrentJobs: 4
```

क्योंकि प्रत्येक निष्पादित प्लान समर्पित [git worktrees](https://git-scm.com/docs/git-worktree) के अंदर काम करता है,
इसलिए एक ही रिपॉजिटरी पर समानांतर जॉब्स टकराती नहीं हैं। हालाँकि, समानांतर रन आपके CPU, मेमोरी, और
कोडिंग एजेंट API दर सीमाओं को साझा करते हैं, इसलिए अपने वर्कस्टेशन के अनुकूल `maxConcurrentJobs` को समायोजित करें।

## लागत ट्रैकिंग

प्रत्येक रन खर्च किए गए टोकन और अनुमानित डॉलर लागत को रिकॉर्ड करता है। स्थायी ऑडिट लॉग प्लान का
`costs.csv` है, जिसमें प्रति रन एक पंक्ति जोड़ी जाती है:

```csv
Promptware,Tokens,Cost,Model,CostSource,Agent
ExecutePlan,148213,1.9042,claude-opus-5,api,claude
```

जब कोई एजेंट बिना मीटर वाले सब्सक्रिप्शन (या Apple Foundation Models जैसे स्थानीय मॉडल) पर चलता है, तो
`Cost` फ़ील्ड शून्य रिकॉर्ड करने के बजाय खाली रहता है, जिससे बिना नकली डॉलर राशि बनाए टोकन मेट्रिक्स सुरक्षित रहते हैं।

## जॉब्स का प्रबंधन और निरीक्षण

डेस्कटॉप ऐप डेमॉन के WebSocket स्ट्रीम के माध्यम से लाइव जॉब स्थिति और स्ट्रीमिंग टर्मिनल आउटपुट प्रदर्शित करता है। CLI पूर्ण समानता प्रदान करता है:

```bash
# List all active and recent jobs
tendril job list

# Filter jobs by status
tendril job list --status Running
tendril job list --status Failed

# Inspect dispatch queue order and available slots
tendril job queue

# Promote a queued or blocked job to run immediately
tendril job force-start <job-id>

# Cancel a running job
tendril job cancel <job-id> -m "Stopping for review"

# Halt every running, queued, and blocked job
tendril job stop-all

# Clean up completed or failed jobs from the database
tendril job clear --completed
tendril job clear --failed
```

प्रत्येक रन के लिए पूर्ण लॉग और ट्रांसक्रिप्ट स्थायी रूप से डिस्क पर
`$TENDRIL_HOME/Jobs/{jobId}-{planId}-{promptware}/` पर संग्रहीत होते हैं, जिसमें रॉ सिस्टम प्रॉम्प्ट, टूल निष्पादन
ट्रेस और एजेंट ट्रांसक्रिप्ट शामिल हैं।
