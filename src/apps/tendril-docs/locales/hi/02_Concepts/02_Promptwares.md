# प्रॉम्प्टवेयर्स (Promptwares)

प्रॉम्प्टवेयर एक डायरेक्टरी है जिसमें निर्देश, टूल्स और मेमोरी शामिल होते हैं जो एक एकल-उद्देश्यीय
वर्कफ़्लो एजेंट को परिभाषित करते हैं। डिप्लॉय की गई प्रतियां `$TENDRIL_HOME/Promptwares/` के अंतर्गत रहती हैं, प्रति प्रॉम्प्टवेयर एक:

- **Program.md** — सिस्टम प्रॉम्प्ट: एजेंट का लक्ष्य, चरण-दर-चरण प्रक्रिया और निष्पादन नियम।
- **Tools/** — निष्पादन योग्य स्क्रिप्ट और उपयोगिताएं जिन्हें एजेंट अपने रन के दौरान कॉल कर सकता है।
- **Memory/** — लगातार बनी रहने वाली मार्कडाउन नोट्स जो रन के बीच सुरक्षित रहती हैं। यह फ़ीडबैक लूप प्रॉम्प्टवेयर्स
  को कोडबेस की विशिष्टताओं को सीखने और त्रुटियों को दोहराने के बजाय सुधार करने की अनुमति देता है।

Tendril आपके कॉन्फ़िगर किए गए कोडिंग एजेंट (जैसे कि
[Claude Code](../06_CodingAgents/01_ClaudeCode.md), [Codex](../06_CodingAgents/02_Codex.md),
[Copilot](../06_CodingAgents/03_Copilot.md), [Gemini](../06_CodingAgents/05_Gemini.md),
[OpenCode](../06_CodingAgents/04_OpenCode.md), Antigravity, या [Cursor](https://www.cursor.com)) के माध्यम से प्रॉम्प्टवेयर्स को डिस्पैच करता है,
और न्यूनतम-विशेषाधिकार प्राप्त टूल अनुमतियों के साथ एक समय में एक जॉब निष्पादित करता है।

## डिप्लॉयमेंट और लेयर्स

Tendril प्लेटफ़ॉर्म में निर्मित प्रॉम्प्टवेयर्स का एक मानक सेट प्रदान करता है। टीमें सिस्टम प्रॉम्प्ट्स को ओवरराइड करने या कस्टम
टीम टूल्स की आपूर्ति करने के लिए [config.yaml](../03_Configuration/01_Setup.md) में एक ओवरले डायरेक्टरी भी कॉन्फ़िगर कर सकती हैं।

प्रॉम्प्टवेयर्स को डिप्लॉय या रीफ़्रेश करें:

```bash
tendril promptware deploy
```

यह जांचने के लिए कि क्या कोई प्रॉम्प्टवेयर शिप किए गए बेसलाइन से चल रहा है या किसी टीम ओवरले से:

```bash
tendril promptware layers
# or check a specific promptware:
tendril promptware layers ExecutePlan
```

## मुख्य वर्कफ़्लो एजेंट्स

| Promptware       | भूमिका                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------- |
| **CreatePlan**   | एक संक्षिप्त विवरण, एक इनबॉक्स आइटम, या [GitHub](https://github.com) इश्यू से एक योजना का ड्राफ़्ट तैयार करना। |
| **ExpandPlan**   | एक संक्षिप्त योजना को चरणों के साथ एक कार्यान्वयन योग्य विनिर्देश में विस्तृत करना।                            |
| **UpdatePlan**   | समीक्षक फ़ीडबैक, चैट और इनलाइन एनोटेशन से मौजूदा योजना को संशोधित करना।                                        |
| **SplitPlan**    | एक बड़ी योजना को छोटी, स्वतंत्र उप-योजनाओं में विभाजित करना।                                                   |
| **ExecutePlan**  | पृथक [git worktrees](https://git-scm.com/docs/git-worktree) बनाना, योजना चरणों को लागू करना, परीक्षण चलाना।    |
| **RetryPlan**    | लॉग और डिफ़्स का उपयोग करके, सत्यापन में विफल रही योजना पर दोबारा प्रयास करना।                                 |
| **CreatePr**     | [GitHub CLI](https://cli.github.com/) (`gh`) का उपयोग करके वर्कस्ट्री डिफ़्स से GitHub पुल रिक्वेस्ट खोलना।    |
| **CreateIssue**  | किसी योजना की विफलता, स्थिति या ट्राइएज अनुरोध को GitHub इश्यूज़ पर भेजना।                                     |
| **AddProject**   | एक नए प्रोजेक्ट को पंजीकृत करना और उसके रिपॉजिटरी पाथ कॉन्फ़िगर करना।                                          |
| **SetupProject** | कोई प्रोजेक्ट कैसे बनता है, चलता है और सत्यापित होता है, इसका पता लगाना और रिकॉर्ड करना।                       |
| **SyncRepo**     | किसी प्रोजेक्ट के रिपॉजिटरीज़ को अपस्ट्रीम शाखाओं के साथ अद्यतित करना।                                         |

## कॉन्फ़िगरेशन

प्रत्येक प्रॉम्प्टवेयर [~/.tendril/config.yaml](../03_Configuration/01_Setup.md) में
`promptwares:` कुंजी के अंतर्गत कॉन्फ़िगर किया गया है:

```yaml
promptwares:
  _default:
    profile: balanced

  CreatePlan:
    profile: deep
    allowedTools:
      - Read
      - Glob
      - Grep
      - Bash
      - Write(%PLANS_DIR%/**)
    deniedTools:
      - WebFetch
    customInstructions: |
      Always include acceptance criteria and verification gates in the plan.
```

| फ़ील्ड               | आवश्यक | विवरण                                                                                                                                                                           |
| -------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `profile`            | हाँ    | किस एजेंट प्रोफ़ाइल का उपयोग करना है — `quick`, `balanced`, या `deep`। प्रोफ़ाइल प्रति एजेंट एक मॉडल और एक प्रयास स्तर पर मैप होती हैं।                                         |
| `allowedTools`       | नहीं   | अंतर्निहित डिफ़ॉल्ट के शीर्ष पर दिए गए टूल्स। टूल अनुमतियों को विशिष्ट पाथ तक सीमित करने के लिए `%PROMPTWARE_DIR%`, `%PLAN_DIR%`, और `%PLANS_DIR%` वेरिएबल्स का समर्थन करता है। |
| `deniedTools`        | नहीं   | रोके गए टूल्स, भले ही किसी अन्य चीज़ ने उन्हें अनुमति दी हो।                                                                                                                    |
| `customInstructions` | नहीं   | प्राथमिकता ओवरराइड मार्करों के साथ एजेंट प्रॉम्प्ट में इंजेक्ट किया गया मुफ़्त टेक्स्ट।                                                                                         |

`_default` प्रविष्टि प्रत्येक प्रॉम्प्टवेयर पर लागू होने वाली बेसलाइन है; एक नामित प्रविष्टि इसे ओवरराइड करती है।

### कस्टम निर्देश

जब `customInstructions` सेट होता है, तो Tendril इसे स्पष्ट प्राथमिकता मार्कर के साथ संकलित फ़र्मवेयर प्रॉम्प्ट में जोड़ता है। एजेंट को फ़र्मवेयर टेम्प्लेट और
प्रॉम्प्टवेयर के अपने `Program.md` दोनों पर इसका पालन करने का निर्देश दिया जाता है। साझा प्रोग्राम फ़ाइलों को संपादित किए बिना
प्रति-प्रॉम्प्टवेयर व्यवहार संबंधी ओवरराइड के लिए इसका उपयोग करें।

## निष्पादन प्रवाह

1. **संदर्भ (Context)** — `Program.md` को संकलित करें, योजना, इनलाइन एनोटेशन, प्रोजेक्ट कॉन्फ़िगरेशन, और
   `config.yaml` से किसी भी `customInstructions` को संलग्न करें।
2. **टूल्स और अनुमतियाँ** — `Tools/` और कॉन्फ़िगर किए गए टूल ग्रांट्स को प्रदर्शित करें, `%...%` वेरिएबल्स को
   पूर्ण पाथ (absolute paths) में विस्तारित करें। लिखने योग्य डायरेक्टरीज़ केवल योजना फ़ोल्डर, प्रॉम्प्टवेयर की
   `Memory/`, और रिपॉजिटरी git worktrees तक ही सीमित हैं।
3. **रन (Run)** — कोडिंग एजेंट को उसके पृथक वर्कस्ट्री में बैकग्राउंड जॉब प्रोसेस के रूप में लॉन्च करें।
4. **कैप्चर और टेलीमेट्री** — लाइव आउटपुट को `$TENDRIL_HOME/Jobs/{jobId}-{planId}-{promptware}/` पर स्ट्रीम करें,
   डेमॉन को प्रगति उत्सर्जित करें, और टोकन उपयोग और लागत को योजना के `costs.csv` में रिकॉर्ड करें।

## मेमोरी और सीखना

मेमोरी एक फ़ीडबैक लूप है: एक प्रॉम्प्टवेयर लिखता है कि उसने किसी प्रोजेक्ट या विफलता मोड के बारे में क्या सीखा,
और भविष्य के रन में इसे वापस पढ़ता है। CLI मेमोरी प्रबंधन को सीधे प्रदर्शित करता है:

```bash
# List stored memory notes for a promptware
tendril promptware list-memory ExecutePlan

# Read specific memory notes
tendril promptware read-memory ExecutePlan worktree-hygiene.md

# Write or update a memory note from a file (or stdin)
tendril promptware write-memory ExecutePlan worktree-hygiene.md --file notes.md

# Delete an obsolete or falsified memory note
tendril promptware delete-memory ExecutePlan worktree-hygiene.md
```

> [!TIP]
> मेमोरी को बढ़ाने के साथ-साथ छांटने (prune करने) के लिए भी डिज़ाइन किया गया है — एक धारणा या नियम जो अप्रचलित हो गया है उसे
> `delete-memory` के साथ हटा दिया जाना चाहिए, न कि विरोधाभासी नोट्स के नीचे दबा दिया जाना चाहिए।

## सीधा निष्पादन

डेमॉन जॉब सेवा को बायपास करते हुए, सीधे फ़ोरग्राउंड में प्रॉम्प्टवेयर का परीक्षण या संचालन करने के लिए:

```bash
# Run CreatePlan directly with a task prompt
tendril promptware run CreatePlan "Add a health-check endpoint" --profile deep

# Print the compiled firmware prompt without launching the agent
tendril promptware run CreatePlan "Add a health-check endpoint" --dry-run
```
