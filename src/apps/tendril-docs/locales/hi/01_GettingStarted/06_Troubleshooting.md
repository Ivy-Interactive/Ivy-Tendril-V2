# समस्या निवारण (Troubleshooting)

सामान्य कॉन्फ़िगरेशन, एजेंट, योजना (plan) और डेटाबेस समस्याओं का निदान और समाधान करें।

## इंस्टॉलेशन और परिवेश (Environment)

| लक्षण                                            | समाधान                                                                                                                                                                                              |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TENDRIL_HOME` नहीं मिला                         | एनवायरनमेंट वेरिएबल सेट करें और अपना टर्मिनल रीस्टार्ट करें, या पाथ को `~/.tendril_location` में लिखें। दोनों के बिना, Tendril डिफ़ॉल्ट रूप से `~/.tendril` का उपयोग करता है।                       |
| `config.yaml` नहीं मिला                          | फ़ाइल `$TENDRIL_HOME/config.yaml` पर मौजूद होनी चाहिए और उसका नाम बिल्कुल यही होना चाहिए — `tendril-config.yaml` नहीं। `tendril doctor` उस पाथ की रिपोर्ट करता है जिसकी वह अपेक्षा करता है।         |
| `gh` प्रमाणित नहीं है                            | [GitHub CLI](https://cli.github.com/) प्रमाणीकरण चलाएं: `gh auth login`, फिर पुष्टि करने के लिए `gh auth status` चलाएं।                                                                             |
| `git` नहीं मिला                                  | [Git](https://git-scm.com/) इंस्टॉल करें और सत्यापित करें कि यह आपके `PATH` में है।                                                                                                                 |
| निर्माण (build) के बाद `tendril` पहचाना नहीं गया | `cargo build --release` बाइनरी को `target/release/tendril` पर छोड़ता है। या तो इसे `PATH` में जोड़ें, या `cargo install --path src/crates/tendril-cli` चलाएं।                                       |
| ऐप शुरू होता है लेकिन कुछ भी लोड नहीं होता है    | डेस्कटॉप ऐप `tendril run` डेमन की निगरानी करता है; यदि पैकेज्ड बिल्ड से साइडकार बाइनरी गायब हैं, तो बात करने के लिए कोई डेमन नहीं है। पैकेजिंग चरणों के लिए [इंस्टॉलेशन](02_Installation.md) देखें। |

## योजनाएं (Plans)

| लक्षण                                                     | समाधान                                                                                                                                                                                   |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| योजना `Draft` में अटकी है                                 | जांचें कि रिपॉजिटरी `tendril plan get <id>` के साथ जुड़ी हुई है, और सत्यापित करें कि प्रोजेक्ट परिभाषा `config.yaml` में मौजूद है।                                                       |
| योजना फ़ोल्डर अधूरा दिखता है या लोड होने में विफल रहता है | समस्याओं का निरीक्षण करने के लिए `tendril plan validate <id>` चलाएं — अमान्य `plan.yaml`, गायब `Revisions/`, खाली शीर्षक, या बेमेल स्कीमा संस्करण।                                       |
| पुरानी स्कीमा पर योजना                                    | योजना फ़ोल्डरों को वर्तमान स्कीमा में माइग्रेट करने के लिए `tendril plan doctor --fix` चलाएं। अनाथ खाली योजना के खोल (husks) को हटाने के लिए, `tendril plan doctor --prune-husks` चलाएं। |
| योजना में कोई रिपॉजिटरी कॉन्फ़िगर नहीं है                 | `tendril plan add-repo <id> <path>` चलाएं।                                                                                                                                               |
| विफल रन के बाद पुराना वर्क-ट्री (stale worktree)          | पूर्ण योजनाओं के लिए वर्क-ट्रीज़ को हटाने के लिए `tendril plan cleanup <id>` चलाएं। गैर-टर्मिनल योजनाओं के लिए, `--force` पास करें: `tendril plan cleanup <id> --force`।                 |

## निष्पादन और एजेंट (Execution & agents)

| लक्षण                          | समाधान                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| एजेंट तक नहीं पहुंचा जा सकता   | `config.yaml` में `codingAgent` की जाँच करें, फिर एजेंट के CLI को सीधे एक साफ़ शेल में चलाएँ। Tendril इसे एक चाइल्ड प्रोसेस के रूप में निष्पादित करता है; यदि `claude`, `codex`, `copilot`, `gemini`, `opencode`, `antigravity`, या `cursor` अप्राप्य (unattended) नहीं चल सकते हैं, तो पृष्ठभूमि कार्य रुक जाएंगे। `apple` के लिए, `fm available` सत्यापित करें और सुनिश्चित करें कि `fm serve` सक्रिय है। |
| निष्पादन तुरंत विफल हो जाता है | `$TENDRIL_HOME/Jobs/{jobId}-{planId}-{promptware}/` के अंतर्गत जॉब लॉग पढ़ें। सामान्य कारणों में रिपॉजिटरी संदर्भ का गायब होना या [Promptwares](../02_Concepts/02_Promptwares.md) में टूल अनुमतियों (tool grants) का गायब होना शामिल है।                                                                                                                                                                    |
| सत्यापन लगातार विफल हो रहे हैं | योजना के पृथक वर्क-ट्री (`$TENDRIL_HOME/Plans/{id}-{name}/Worktrees/{repo}`) के अंदर सत्यापन कमांड को मैन्युअल रूप से चलाएं। कमांड आमतौर पर सही होती है और वर्क-ट्री में सेटअप चरण छूट जाता है — [कोडबेस को ऑनबोर्ड करना](03_Onboarding.md) देखें।                                                                                                                                                          |
| कार्य कभी शुरू नहीं होता       | प्रेषण क्रम और समवर्ती सीमाओं (`config.yaml` में `maxConcurrentJobs`) का निरीक्षण करने के लिए `tendril job queue` चलाएं। कतारबद्ध या अवरुद्ध कार्य को `tendril job force-start <id>` के साथ बढ़ावा दें, या अटके हुए कार्यों को `tendril job stop-all` के साथ रोकें। [लाइफसाइकिल और जॉब्स](../02_Concepts/03_Lifecycle.md) देखें।                                                                            |
| वॉयस इनपुट अनुपलब्ध बताता है   | macOS पर, System Settings → Privacy & Security → Microphone के तहत माइक्रोफ़ोन अनुमतियां प्रदान करें, फिर डेस्कटॉप ऐप को पुनः आरंभ करें।                                                                                                                                                                                                                                                                    |

## डेटाबेस (Database)

Tendril अपने [SQLite](https://www.sqlite.org) डेटाबेस को `$TENDRIL_HOME/tendril.db` पर प्रबंधित करता है। जबकि डेमन स्टार्टअप पर माइग्रेशन
स्वचालित रूप से चलते हैं, Tendril समर्पित डेटाबेस कमांड प्रदान करता है:

```bash
# Check current database schema version
tendril db version

# Apply any pending migrations
tendril db migrate

# Verify database integrity
tendril db integrity

# Reclaim unused disk space
tendril db vacuum

# Reset database (prompted confirmation)
tendril db reset
```

| लक्षण                                     | समाधान                                                                                                                                                                                                                        |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| अनिश्चित हैं कि डेटाबेस स्वस्थ है या नहीं | आंतरिक SQLite स्थिरता की जांच के लिए `tendril doctor` (कनेक्टिविटी सत्यापित करता है) या `tendril db integrity` चलाएं।                                                                                                         |
| डेटाबेस लॉक है                            | किसी अन्य प्रक्रिया के पास विशेष लॉक है। एक समय में केवल एक डेमन चलना चाहिए; मैन्युअल रूप से `tendril run` या `tendril serve` चलाने से पहले डेस्कटॉप ऐप बंद करें।                                                             |
| डेटाबेस दूषित (corrupted) है              | ऐप और डेमन को रोकें, फिर `tendril db reset` चलाएं (या `$TENDRIL_HOME/tendril.db` को `-wal` और `-shm` फ़ाइलों के साथ हटा दें)। डिस्क पर `$TENDRIL_HOME/Plans/` के अंतर्गत योजना मार्कडाउन फ़ाइलें पूरी तरह से बरकरार रहती हैं। |

> [!TIP]
> [Discord](https://discord.gg/FHgxkDga3y) या GitHub पर सहायता का अनुरोध करते समय, `tendril report-bug <plan-id>` का उपयोग करके पूर्ण डायग्नोस्टिक लॉग बंडल करें — [सहायता प्राप्त करना](05_GettingHelp.md) देखें।
