# कोडबेस को ऑनबोर्ड करना

Tendril आपके रिपॉजिटरी पर एक अलग [Git worktree](https://git-scm.com/docs/git-worktree) के अंदर कोडिंग एजेंट चलाता है, फिर बिल्ड करता है, टेस्ट करता है और एक पुल रिक्वेस्ट खोलता है। इस लूप के बिना किसी मानवीय हस्तक्षेप के सफल होने के लिए, मशीन और रिपॉजिटरी को पहले से कॉन्फ़िगर किया जाना चाहिए। नीचे दी गई चेकलिस्ट पर प्रति मशीन एक बार और प्रति कोडबेस एक बार काम करें।

> [!TIP]
> जब आपका काम पूरा हो जाए, तो `tendril doctor` चलाएं। यह Tendril होम, `config.yaml`, डेटाबेस, प्लान्स डायरेक्टरी, `git` और `gh` की पुष्टि करता है। यह आपके कोडिंग एजेंट का परीक्षण **नहीं** करता है — नीचे दिए गए चरण 2 के साथ इसे स्वयं सत्यापित करें।

## मशीन चेकलिस्ट

### 1. आवश्यक बिल्ड सॉफ़्टवेयर इंस्टॉल है

प्रोजेक्ट को कंपाइल करने के लिए आवश्यक प्रत्येक टूल इंस्टॉल होना चाहिए और आपके `PATH` पर उपलब्ध होना चाहिए। एजेंट रन के बीच में किसी अनुपलब्ध कंपाइलर या SDK को इंस्टॉल नहीं कर सकता। Tendril के अपने Rust और pnpm रेपो जैसे रिपॉजिटरी के लिए, इसका मतलब [Rustup](https://rustup.rs/), [Node.js](https://nodejs.org/), और [pnpm](https://pnpm.io/) है; आपके प्रोजेक्ट के लिए इसका अर्थ वह बिल्ड टूलचेन है जिसे आपकी स्क्रिप्ट्स इनवोक करती हैं।

> [!NOTE]
> लक्षित आवश्यकता: एक नया क्लोन बिना किसी इंटरैक्टिव प्रॉम्प्ट और बिना किसी केवल-IDE मैन्युअल चरणों के, डॉक्यूमेंटेड कमांड्स का उपयोग करके एक साफ़ टर्मिनल से बिल्ड हो सके।

### 2. पसंदीदा कोडिंग CLI इंस्टॉल और प्रमाणित है

उस एजेंट को इंस्टॉल करें जिसे आपने `config.yaml` में `codingAgent` के रूप में सेट किया है और लॉग इन करें ताकि यह नॉन-इंटरैक्टिव रूप से निष्पादित हो सके:

```bash
# Example: Claude Code
npm install -g @anthropic-ai/claude-code
claude login
```

सत्यापित करें कि CLI `PATH` पर है और एक सामान्य इनवोकेशन क्रेडेंशियल्स के लिए प्रॉम्प्ट करने के लिए नहीं रुकता है:

- [Claude Code](https://code.claude.com/docs) (`claude`)
- [OpenAI Codex](https://openai.com) (`codex`)
- [GitHub Copilot](https://github.com/features/copilot) (`copilot`)
- [Google Gemini](https://ai.google.dev) (`gemini`)
- [OpenCode](https://opencode.ai) (`opencode`)
- Antigravity (`antigravity` / `agy`)
- [Cursor](https://www.cursor.com) (`cursor` / `cursor-agent`)
- Apple Foundation Models (`apple` via on-device `fm`)

`apple` एजेंट अपवाद है: यह Apple के ऑन-डिवाइस मॉडल के विरुद्ध बंडल किए गए OpenCode के माध्यम से चलता है, इसलिए सुनिश्चित करें कि `fm` इंस्टॉल है (`fm available` से सत्यापित करें) और एक `fm serve` प्रक्रिया पहले से सुन रही है।

### 3. Git इंस्टॉल है और अनअटेंडेड उपयोग के लिए अधिकृत है

Tendril आपकी ओर से कोड पुल करता है, वर्क-ट्री बनाता है, कमिट करता है और पुश करता है। पुष्टि करें कि सभी ऑपरेशन बिना किसी इंटरैक्टिव प्रॉम्प्ट के काम करते हैं:

- एक ग्लोबल पहचान कॉन्फ़िगर की गई है (`git config --global user.name` और `user.email`)।
- क्रेडेंशियल्स को क्रेडेंशियल हेल्पर या एजेंट में लोड की गई SSH कुंजी के माध्यम से कैश किया जाता है, ताकि `git pull` और `git push` कभी भी पासवर्ड के लिए प्रॉम्प्ट न करें।
- वर्क-ट्री जोड़े और हटाए जा सकते हैं (`git worktree add` और `git worktree remove`)।

> [!WARNING]
> यदि HTTPS पर पुश करने से क्रेडेंशियल्स के लिए प्रॉम्प्ट आता है, तो एक क्रेडेंशियल हेल्पर कॉन्फ़िगर करें या सक्रिय `ssh-agent` के साथ SSH कुंजी का उपयोग करें। एक भी इंटरैक्टिव प्रॉम्प्ट अन्यथा अनअटेंडेड रहने वाले काम को रोक देगा।

### 4. GitHub CLI इंस्टॉल और प्रमाणित है

[CreatePr](../02_Concepts/02_Promptwares.md) पुल रिक्वेस्ट खोलने के लिए [GitHub CLI](https://cli.github.com/) (`gh`) का उपयोग करता है। इसे इंस्टॉल करें और प्रमाणीकरण सत्यापित करें:

```bash
gh auth login
gh auth status
```

### 5. आवश्यक MCP सर्वर विश्व स्तर पर इंस्टॉल हैं

यदि आप [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) सर्वरों पर भरोसा करते हैं — जैसे कि इश्यू संदर्भ के लिए Jira या UI डिज़ाइन के लिए Figma — तो उन्हें विश्व स्तर पर इंस्टॉल और पंजीकृत करें ताकि प्रत्येक वर्क-ट्री उन तक पहुंच सके। MCP सर्वर कोडिंग एजेंट पर पंजीकृत होते हैं, Tendril के अंदर नहीं:

```bash
# Example: register an MCP server globally for Claude Code
claude mcp add --scope user jira -- npx -y @your-org/jira-mcp
claude mcp add --scope user figma -- npx -y figma-developer-mcp
claude mcp list   # verify they are reachable
```

> [!NOTE]
> ग्लोबल या यूज़र स्कोप का उपयोग करें, प्रोजेक्ट स्कोप का नहीं, ताकि MCP सर्वर उन अल्पकालिक git वर्क-ट्री में बने रहें जिनमें एजेंट काम करता है। किसी भी आवश्यक API टोकन को अपने सिस्टम पर पर्यावरण चर के रूप में संग्रहीत करें।

सुनिश्चित करें कि आप वास्तव में प्रत्येक MCP सर्वर पर _प्रमाणित_ हैं, न कि केवल यह कि वह पंजीकृत है। Tendril से एक छोटा परीक्षण प्लान निष्पादित करें और पुष्टि करें कि प्रत्येक सर्वर OAuth मोडल ट्रिगर किए बिना इनिशियलाइज़ होता है।

## रिपॉजिटरी चेकलिस्ट

### 6. रेपो वर्क-ट्री के लिए तैयार है

[ExecutePlan](../02_Concepts/02_Promptwares.md) आपकी सक्रिय कार्यशील निर्देशिका में नहीं, बल्कि एक अलग [Git worktree](https://git-scm.com/docs/git-worktree) के अंदर चलता है। एक वर्क-ट्री एक साफ़ कमिट से शुरू होता है — कोई `target/`, `node_modules/`, या अनट्रैक्ड `.env` फ़ाइलें मौजूद नहीं होती हैं।

- कोड कंपाइल होने से पहले चेकआउट के बाद आवश्यक किसी भी सेटअप कमांड का दस्तावेजीकरण करें (उदा. निर्भरता पुनर्स्थापना, कोड जनरेशन, नमूना `.env` प्रतियां), और एक कमिट की गई सेटअप स्क्रिप्ट प्रदान करें।
- उन अनकमिटेड फ़ाइलों पर निर्भर न रहें जो केवल आपके प्राथमिक चेकआउट में मौजूद हैं।
- एक केंद्रीकृत कैश वाले पैकेज मैनेजर का उपयोग करें ताकि प्रत्येक वर्क-ट्री पैकेज को फिर से डाउनलोड करने के बजाय सेकंडों में रीस्टोर हो जाए (उदा. pnpm स्टोर, Cargo रजिस्ट्री कैश, या Go मॉड्यूल कैश)।

> [!TIP]
> त्वरित परीक्षण: `git worktree add ../repo-probe` चलाएं, फिर एक साफ़ शेल से उस डायरेक्टरी में अपने दस्तावेज़ीकृत बिल्ड कमांड निष्पादित करें। यदि यह कंपाइल होता है और टेस्ट पास करता है, तो Tendril भी सफल होगा। इसे `git worktree remove ../repo-probe` के साथ हटाएं।

### 7. प्रत्येक ऐप के लिए एक रन स्क्रिप्ट लिखें

कॉन्फ़िगर करने योग्य पोर्ट के साथ रिपॉजिटरी में प्रत्येक एप्लिकेशन के लिए एक छोटी, कमिट की गई लॉन्च स्क्रिप्ट प्रदान करें। Tendril वर्क-ट्री में एक साथ समानांतर प्लान्स चला सकता है, इसलिए हार्ड-कोड किए गए पोर्ट पोर्ट टकराव का कारण बनते हैं।

[Vite](https://vite.dev) फ्रंटएंड और Python API युग्म के लिए, स्क्रिप्ट कुछ इस तरह दिख सकती है:

```bash
#!/usr/bin/env bash
# run.sh - launch the Python backend API and the Vite frontend
set -euo pipefail

api_port="${API_PORT:-8000}"
web_port="${WEB_PORT:-5173}"

cd "$(dirname "$0")"

# Backend: configure virtualenv and install dependencies
python -m venv .venv
source .venv/bin/activate
pip install -q -r requirements.txt

# Start backend API on its dedicated port
uvicorn app.main:app --port "$api_port" &
api_pid=$!

# Terminate backend when the frontend process exits
trap 'kill "$api_pid" 2>/dev/null' EXIT

# Frontend: install dependencies and start Vite dev server
npm --prefix web install --prefer-offline --no-audit
npm --prefix web run dev -- --port "$web_port" --open
```

> [!NOTE]
> स्टार्टअप कमांड्स को एक कमिट की गई स्क्रिप्ट में रखने से यह सुनिश्चित होता है कि डेवलपर्स और स्वायत्त वर्कफ़्लो एजेंट दोनों एप्लिकेशन को समान रूप से लॉन्च करते हैं।

### 8. रेपो रूट पर एक AGENTS.md (या README.md) जोड़ें

वर्कफ़्लो एजेंटों को वह मूलभूत संदर्भ प्रदान करें जिसकी उन्हें बिना किसी अनुमान के कोडबेस को नेविगेट करने के लिए आवश्यकता है:

- कोड को बिल्ड और रन करने के लिए आवश्यक **पूर्वापेक्षाएँ**।
- एप्लिकेशन, लाइब्रेरी और संचार प्रोटोकॉल का विवरण देने वाला **आर्किटेक्चरल मैप**।
- रिपॉजिटरी को कंपाइल और सत्यापित करने वाले **बिल्ड और टेस्ट कमांड्स**।
- पिछले चरण की लॉन्च स्क्रिप्ट्स को इंगित करने वाली **रन स्क्रिप्ट्स**।
