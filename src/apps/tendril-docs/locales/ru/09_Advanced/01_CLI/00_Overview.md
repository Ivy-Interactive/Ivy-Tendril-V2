# Обзор CLI

Управляйте планами, проектами, базами данных и агентами прямо из терминала. Бинарный файл `tendril` работает как серверный демон и полнофункциональный инструмент CLI.

Tendril CLI предоставляет полный контроль над рабочим процессом без необходимости открывать графический интерфейс:

- **Планы** — создание, просмотр списка, обновление и инспекция планов; управление репозиториями, рабочими деревьями (worktrees), проверками и рекомендациями
- **Проекты** — настройка проектов, их репозиториев, зависимостей сборки, действий ревью, серверов MCP и пользовательских навыков
- **Проверки** — определение и управление переиспользуемыми проверками (verifications)
- **Конфигурация** — чтение и обновление параметров верхнего уровня, хранящихся в `config.yaml`
- **Хранилище (Vault)** — подключение командных хранилищ, обнаружение удаленных репозиториев, синхронизация ресурсов, а также импорт и отправка проектов
- **База данных** — запуск миграций, проверка версий схемы, сброс таблиц, проверка целостности и очистка (vacuum)
- **Агенты и задачи** — запуск promptware, управление фоновыми задачами и проведение интерактивных чат-сессий

## Быстрый старт

**1. Проверьте вашу установку**

```terminal
>tendril doctor
```

**2. Запустите сервер-демон**

```terminal
>tendril run
```

**3. Создайте новый план**

```terminal
>tendril plan create "Fix login bug" MyProject
```

**4. Выведите список активных планов**

```terminal
>tendril plan list --state Executing
```

**5. Сбросьте всё и начните заново**

```terminal
>tendril reset
```

> [!TIP]
> Каждая команда поддерживает флаг `--help` для подробной справки по использованию. Например: `tendril plan create --help`.

## Глобальные параметры

| Флаг            | Назначение                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------------- |
| `--home <path>` | Путь к домашней директории Tendril (также может быть задан через переменную окружения `TENDRIL_HOME`) |

## Переменные окружения

| Переменная      | Назначение                                                                                                                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TENDRIL_HOME`  | Корневая директория для конфигурации, базы данных, входящих сообщений (inbox) и планов (по умолчанию `~/.tendril` или `D:\.tendril`)                                                                    |
| `TENDRIL_PLANS` | Переопределение директории планов (по умолчанию `TENDRIL_HOME/Plans`)                                                                                                                                   |
| `RUST_LOG`      | Директива фильтрации для логирования процессов в stderr (по умолчанию: `warn,tendril_cli=info,tendril_core=info,tendril_server=info`). Установите значение `debug` для подробных диагностических логов. |

## Основные команды

#### doctor

```terminal
>tendril doctor
>tendril doctor --rebuild-search-index
```

Проверяет корректность установки Tendril — проверяет `TENDRIL_HOME`, `config.yaml`, необходимые инструменты (`git`, `gh`), подключение к базе данных и доступность моделей агентов. Используйте `--rebuild-search-index` для повторной генерации полнотекстового поискового индекса из базы данных.

#### plan doctor

```terminal
>tendril plan doctor
>tendril plan doctor --fix
>tendril plan doctor --prs
>tendril plan doctor --prune-husks --dry-run
```

Сканирует каждую папку плана и сообщает о состоянии: отсутствие или повреждение `plan.yaml`, устаревшие рабочие деревья и планы, оставшиеся в статусе `Completed` при непройденной проверке. Полный список параметров и кодов состояния см. в разделе [Plan](01_Plan.md#doctor).

#### serve и run

```terminal
>tendril serve --port 5010 --host 127.0.0.1
>tendril serve --tls-cert /path/localhost.crt --tls-key /path/localhost.key
>tendril run
```

`tendril serve` запускает HTTP и WebSocket API сервер (порт по умолчанию `5010`, хост `127.0.0.1`). Опциональные флаги `--tls-cert` и `--tls-key` используются для работы по HTTPS.

`tendril run` проверяет доступность целевого порта, автоматически применяет все ожидающие миграции базы данных и затем запускает демон.

#### reset

```terminal
>tendril reset
>tendril reset --force
```

Удаляет все данные Tendril с компьютера — удаляет `TENDRIL_HOME` и `TENDRIL_PLANS`. Запрашивает подтверждение, если не передан флаг `--force`.

> [!WARNING]
> Это действие навсегда удалит все планы, задачи и данные конфигурации в целевых директориях.

#### report-bug

```terminal
>tendril report-bug --plan 00042
>tendril report-bug --job 00150 -d "Agent failed to create worktree"
>tendril report-bug --plan 00042 --out ~/Desktop/diagnostics.zip
>tendril report-bug --plan 00042 --submit --yes
```

Собирает файлы плана и все артефакты задачи — Job Log, Job Prompt, Job Raw Log и Job Eventwire Log из `<TendrilHome>/Jobs/` — в zip-архив с очищенной от конфиденциальных данных конфигурацией и диагностикой состояния. При указании параметров `--submit` и `--yes` загружает архив и создает issue на GitHub.

| Параметр                | Назначение                                                        |
| ----------------------- | ----------------------------------------------------------------- |
| `--plan <id>`           | Включить папку указанного плана и все задачи, запущенные для него |
| `--job <id>`            | Включить четыре артефакта этой задачи плюс контекст ее плана      |
| `-d, --description <t>` | Описание ошибки (запрашивается интерактивно, если опущено)        |
| `--out <path>`          | Путь назначения для zip-архива                                    |
| `--github-user <name>`  | Имя пользователя GitHub для отслеживания issue                    |
| `--submit`              | Загрузить отчет на GitHub (требуется `--yes`)                     |
| `-y, --yes`             | Пропустить запрос подтверждения                                   |

> [!WARNING]
> Отправка отчета прикрепляет zip-архив к **публичному** issue на GitHub. Секреты удаляются из конфигураций и логов задач, но перед отправкой обязательно проверьте содержимое плана.

#### version

```terminal
>tendril version
```

Выводит установленную версию Tendril (например, `tendril v2.0.0`).

#### update-promptwares

```terminal
>tendril update-promptwares
>tendril update-promptwares --dry-run
>tendril update-promptwares --source /path/to/promptwares
```

Обновляет развернутые promptwares в `<TendrilHome>/Promptwares/`, сохраняя их директории `Memory/` и `Tools/`.
