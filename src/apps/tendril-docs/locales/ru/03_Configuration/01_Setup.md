# Установка и настройки

## Настройки в приложении (In-app Settings)

Tendril включает специальное приложение Settings для визуальной настройки окружения без необходимости ручного редактирования [YAML](https://yaml.org). Боковая панель настроек содержит следующие разделы:

- **Coding Agent** — выбор основного рантайма кодинг-агента ([Claude Code](../06_CodingAgents/01_ClaudeCode.md), [Copilot](../06_CodingAgents/03_Copilot.md), [Codex](../06_CodingAgents/02_Codex.md), [Gemini](../06_CodingAgents/05_Gemini.md), Antigravity, [OpenCode](../06_CodingAgents/04_OpenCode.md), Cursor, Apple или кастомные OpenAI-совместимые прокси), настройка ключей API провайдеров и базовых URL, настройка профилей агентов и уровней рассуждений (reasoning tiers), проверка подключения к агентам и просмотр каталога моделей (Model Catalog). Инструкции по установке и настройке агентов приведены в разделе [Кодинг-агенты](../06_CodingAgents/_Index.md).
- **Plans** — редактирование шаблона плана по умолчанию (`planTemplate`), используемого при создании каждого нового плана в приложении [Планы](../04_Apps/03_Plans.md).
- **Appearance** — выбор темы оформления (**Light**, **Dark** или **System**), выбор из готовых предустановок тем с образцами предпросмотра, настройка стандартного состояния боковой панели (развёрнута или свёрнута) и выбор действия кнопки Chat (**Chat view** или **Terminal**).
- **Projects** — управление зарегистрированными проектами, настройка репозиториев для каждого проекта, проверок верификации, портов, переменных окружения, пользовательских навыков, серверов [MCP](../09_Advanced/03_MCP.md) и доступ к «Опасной зоне» (Danger Zone). См. [Настройка проектов](02_Projects.md).
- **Team Vault** _(Бета)_ — синхронизация проектов, пользовательских навыков, серверов MCP и правил безопасности между участниками команды через общий репозиторий [Git](https://git-scm.com).
- **Workflow Agents** — настройка профилей агентов [Promptware](../02_Concepts/02_Promptwares.md) и детальных прав доступа к инструментам (`allowedTools`, `deniedTools`) для стандартных рабочих процессов (`CreatePlan`, `ExecutePlan`, `UpdatePlan` и др.) или глобально через ключ `_default`.
- **Levels** — определение уровней сложности (таких как L1, L2, L3) с относительными весами выполнения, описаниями и цветами бейджей.
- **Notifications** — включение или выключение системных уведомлений операционной системы о завершении или сбое заданий.
- **Security & Tunneling** — настройка защиты веб-сессий паролем, запуск или остановка полнодоступных туннелей [Cloudflare](https://www.cloudflare.com) для удалённого доступа и создание туннелей совместного доступа только для чтения с токенами возможностей.
- **Advanced** — настройка таймаутов выполнения (`jobTimeout`, `staleOutputTimeout`), регулировка `maxConcurrentJobs`, переключение доступа к бета-функциям и проверка **Диагностики демона** в реальном времени (статус подключения, PID, пинг задержки, путь `$TENDRIL_HOME` и заявленные возможности).
- **Newsletter** — подписка на обновления продуктов Ivy и Tendril и примечания к релизам.
- **Open config.yaml** — запуск встроенного редактора чистого YAML с подсветкой синтаксиса и прямыми ссылками на планы.

## `config.yaml`

Настройки, изменённые в интерфейсе, немедленно сохраняются в `$TENDRIL_HOME/config.yaml` (по умолчанию `~/.tendril/config.yaml`). Вы также можете редактировать этот файл напрямую или указать пользовательский путь через переменную окружения `TENDRIL_CONFIG`.

> [!NOTE]
> Конфигурационный файл обязательно должен называться `config.yaml`. Демон Tendril автоматически перезагружает изменения конфигурации при обновлении файла на диске.

### Пример

```yaml
codingAgent: claude
maxConcurrentJobs: 5
jobTimeout: 45
staleOutputTimeout: 10
theme: default
themeMode: system
chatMode: chat
desktopNotifications: true

projects:
  - name: Global Engine
    color: Emerald
    repos:
      - path: ~/repos/global-engine
    verifications:
      - name: Build
        required: true
      - name: Test
        required: true
      - name: CheckResult
        required: true

auth:
  username: admin
  password: "$argon2id$v=19$m=65536,t=3,p=4$..." # Управляется через Settings
  hashSecret: "base64-secret-pepper"

api:
  apiKey: "your-api-secret-key"
```

### Общие поля

| Поле                   | Тип         | По умолчанию | Назначение                                                                                            |
| ---------------------- | ----------- | ------------ | ----------------------------------------------------------------------------------------------------- |
| `codingAgent`          | строка      | `"claude"`   | Исполняемый файл кодинг-агента по умолчанию. См. [Кодинг-агенты](../06_CodingAgents/_Index.md).       |
| `maxConcurrentJobs`    | целое число | `20`         | Максимальное количество одновременно выполняемых [Заданий](../04_Apps/04_Jobs.md) (worktrees).        |
| `jobTimeout`           | целое (мин) | `30`         | Таймаут выполнения в минутах перед отменой активного задания.                                         |
| `staleOutputTimeout`   | целое (мин) | `10`         | Таймаут в минутах, если процесс агента не производит вывод в stdout/stderr.                           |
| `daemonRequestTimeout` | целое (сек) | `30`         | Таймаут клиентского запроса в секундах при обращении к локальному демону.                             |
| `planTemplate`         | строка      | `""`         | Шаблон Markdown, используемый при создании новых планов в приложении [Планы](../04_Apps/03_Plans.md). |
| `theme`                | строка      | `"default"`  | Идентификатор предустановки темы оформления (например, `default`, `dracula`).                         |
| `themeMode`            | строка      | `"system"`   | Режим темы: `light`, `dark` или `system`.                                                             |
| `chatMode`             | строка      | `"chat"`     | Что открывает кнопка Chat: `chat` (вид чата) или `terminal` (терминал агента).                        |
| `desktopNotifications` | булево      | `true`       | Включены ли уведомления ОС о событиях заданий.                                                        |
| `projects`             | список      | `[]`         | Список зарегистрированных проектов и их конфигураций. См. [Настройка проектов](02_Projects.md).       |
| `levels`               | список      | стандартно   | Настроенные уровни сложности планов и их веса.                                                        |
| `auth`                 | объект      | `null`       | Настройка парольной защиты сессий с помощью [Argon2](https://en.wikipedia.org/wiki/Argon2).           |
| `api.apiKey`           | строка      | `null`       | Общий секретный ключ для защиты REST API эндпоинтов. См. [REST API](../09_Advanced/02_REST.md).       |
| `telemetry`            | булево      | `null`       | Согласие на сбор анонимной телеметрии (`false` или отсутствие ключа означает отключение).             |

## Аутентификация и удалённый доступ

### Защита сессий (Веб-интерфейс)

При размещении Tendril на удалённом сервере или предоставлении доступа по сети включите защиту сессий в **Settings > Security & Tunneling** или настройте учётные данные через переменные окружения:

- `TENDRIL_AUTH_USERNAME` — имя пользователя для входа (по умолчанию: `admin`).
- `TENDRIL_AUTH_PASSWORD` — открытый пароль, хэшируемый при запуске.
- `TENDRIL_AUTH_HASH_SECRET` — 32-байтовая строка base64 (`openssl rand -base64 32` через [OpenSSL](https://www.openssl.org)), используемая в качестве соли/перца (pepper) для [Argon2](https://en.wikipedia.org/wiki/Argon2).

В `config.yaml` пароли хранятся как PHC-хэши Argon2 в блоке `auth:` с возможностью настройки ограничения частоты запросов (rate limiting):

```yaml
auth:
  username: admin
  password: "$argon2id$v=19$m=65536,t=3,p=4$..."
  hashSecret: "base64-encoded-pepper"
  rateLimit:
    threshold: 3
    baseDelaySeconds: 1.0
    maxDelaySeconds: 60.0
```

### Туннели Cloudflare

Tendril интегрируется с туннелями [Cloudflare](https://www.cloudflare.com) (`cloudflared`) для безопасного доступа к приложению без открытия входящих портов в брандмауэре:

- **Полнодоступный туннель (Full-Access Tunnel)**: публикует полный интерфейс демона Tendril. В целях безопасности Tendril требует, чтобы перед запуском такого туннеля была обязательно активирована защита сессий с настроенным паролем.
- **Туннель совместного доступа (Share Tunnel)**: создаёт туннель только для чтения, защищённый токенами возможностей, позволяя безопасно демонстрировать [Панель управления](../04_Apps/01_Dashboard.md) и прогресс планов заинтересованным сторонам без предоставления прав на запись.

### Защита REST API

REST API использует токенную аутентификацию через параметр `api.apiKey` в `config.yaml` или переменную окружения `TENDRIL_API_KEY`. Если параметр задан, запросы должны содержать заголовок `X-Api-Key`. См. [REST API](../09_Advanced/02_REST.md) и [Конфигурация CLI](../09_Advanced/01_CLI/06_Config.md).

## Верификации

Tendril поставляется со встроенными определениями этапов верификации, которые проекты могут включать в свои конвейеры:

| Верификация   | Описание                                                        |
| ------------- | --------------------------------------------------------------- |
| `Build`       | Запуск команды сборки проекта и проверка отсутствия ошибок.     |
| `Format`      | Проверка правил форматирования кода или форматирование файлов.  |
| `Test`        | Запуск модульных или интеграционных тестов для изменений плана. |
| `Lint`        | Запуск статического анализа / линтеров и отчёт о нарушениях.    |
| `Screenshots` | Сохранение скриншотов интерфейса в каталог артефактов плана.    |
| `CheckResult` | Проверка соответствия итоговой реализации спецификации плана.   |

Пользовательские команды верификации (такие как `cargo test`, `pnpm test` или `pytest`) могут определяться глобально в `config.yaml` или непосредственно в разделе [Настройка проектов](02_Projects.md#конвейеры-верификации). Инструкции по управлению верификациями из CLI приведены в разделе [Верификация через CLI](../09_Advanced/01_CLI/03_Verification.md).
