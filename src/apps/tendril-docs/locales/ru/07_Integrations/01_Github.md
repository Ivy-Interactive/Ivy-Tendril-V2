# GitHub

## Аутентификация

Tendril использует [GitHub CLI](https://cli.github.com) (`gh`) для аутентификации в [GitHub](https://github.com). Выполните команду `gh auth login` для аутентификации перед использованием функций GitHub.

> [!NOTE]
> Убедитесь, что `gh` установлен и доступен в вашей переменной PATH. Tendril предупредит вас на этапе адаптации (onboarding), если он отсутствует.

## Импорт задач через Inbox

Tendril предоставляет специальный раздел **Inbox** на боковой панели для просмотра задач [GitHub](https://github.com) и превращения их в [планы](../02_Concepts/01_Plans.md):

1. Откройте **Inbox** на панели навигации.
2. Выберите категорию:
   - **My Issues**: Задачи, назначенные вам в настроенных репозиториях проектов.
   - **Review Requests**: Открытые пул-реквесты, ожидающие вашего ревью.
   - **Project Issues**: Все открытые задачи для выбранного репозитория проекта.
3. Фильтруйте по поисковым запросам, меткам (labels) или этапам (milestones). Один запрос возвращает до 1 000 открытых задач (лимит поиска GitHub).
4. Выберите одну или несколько задач и нажмите **Create Plan**, чтобы запустить [promptware](../02_Concepts/02_Promptwares.md) `CreatePlan`, или настройте описание плана в диалоговом окне New Plan перед запуском.

Каждый созданный план сохраняет исходный URL-адрес, ведущий непосредственно к оригинальной задаче на GitHub.

### Автоматический опрос задач и предложения

Tendril включает автоматический фоновый опрос назначенных задач GitHub:

- Настройте `inbox.checkIntervalMinutes` (или нажмите на значок шестеренки «Settings» в разделе Inbox), чтобы задать частоту запросов Tendril к GitHub для поиска новых назначенных задач.
- **Режим автопринятия (Auto-Accept Mode)**: Когда включен параметр `inbox.autoAcceptAssignedIssues`, для вновь обнаруженных задач немедленно запускается задача `CreatePlan`.
- **Режим предложений (Proposals Mode)**: Когда параметр отключен, обнаруженные задачи помещаются в раздел Inbox как **Inbox Proposals**. Вы можете просмотреть описание каждого предложения и выбрать **Accept** (для запуска плана) или **Dismiss** (сохранив постоянную запись о том, что задачу не следует импортировать повторно).
- Нажмите **Check Now** на панели инструментов Inbox, чтобы выполнить немедленный опрос вручную, не дожидаясь срабатывания таймера.

## Создание пул-реквестов

Когда план завершен и изменения проверены, откройте диалоговое окно **Create PR** для создания пул-реквеста:

1. Просмотрите и отредактируйте сгенерированные название PR, описание и список проверяющих (reviewers).
2. Настройте параметры PR:
   - **Solve Merge Conflicts**: Автоматически пытается разрешить конфликты слияния ветки с целевой базовой веткой.
   - **Merge**: Выполняет слияние PR после прохождения проверок (снимите флажок, чтобы открыть PR для ревью командой без слияния).
   - **Delete Branch**: Удаляет ветку worktree после слияния.
   - **Include Artifacts**: Прикрепляет артефакты проверки плана, скриншоты и логи к описанию PR.
   - **Create as Draft**: Создает пул-реквест в статусе черновика (draft).
3. Tendril запускает [promptware](../02_Concepts/02_Promptwares.md) `CreatePr` через `gh`, чтобы отправить ветку, создать пул-реквест и привязать URL-адрес PR к плану.

## Отслеживание статуса PR

Раздел [Pull Requests](../04_Apps/06_PullRequests.md) на боковой панели отслеживает все открытые, объединенные (merged) и закрытые пул-реквесты по всем вашим проектам. Tendril отслеживает изменения состояния PR, автоматически синхронизируя вашу [доску планов](../04_Apps/03_Plans.md) без ручного вмешательства.
