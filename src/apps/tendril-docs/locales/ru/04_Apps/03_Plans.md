# Планы

Приложение «Планы» (Plans) — это рабочее пространство Tendril для формирования, доработки и подготовки инженерных задач перед выполнением изменений в коде. Предварительная работа над планами гарантирует ясность требований, архитектуры и шагов верификации до запуска выполнения задач агентами.

## Управление черновиками

- **Создание планов** — Нажмите `Ctrl+Alt+N` (`Cmd+Option+N` в macOS) или кликните **+ New Plan** в заголовке оболочки, чтобы открыть диалоговое окно создания.
- **Очередь черновиков** — В боковой панели перечислены все планы в статусе `Draft` или `Blocked`. Планы, выполняемые в данный момент в рамках рабочих задач (jobs), безопасно скрываются из очереди черновиков во избежание одновременного редактирования.
- **Бейджи** — Для каждого черновика отображаются его тег `#ID`, заголовок, бейдж проекта и бейдж уровня сложности (например, L1, L2, L3), оформленный в соответствии с настроенной палитрой уровней проекта.
- **Интерактивная заставка процесса** — Когда очередь пуста, Tendril отображает интерактивную заставку жизненного цикла процесса с навигацией к разделам «Планы», [Проверка](02_Review.md) и [Задачи](04_Jobs.md).

## Рабочее пространство плана (`PlanWorkspace`)

При выборе плана открывается многофункциональный интерфейс рабочего пространства:

### Вкладки

- **План** — Отображает последнюю ревизию спецификации плана в формате [Markdown](https://www.markdownguide.org) с интерактивными чек-листами задач, описанием проблемы, предлагаемым подходом и критериями верификации.
- **Детали** — Метаданные плана, контекст назначенного проекта (из [Настройки проектов](../03_Configuration/02_Projects.md)), метки времени создания/обновления и история ревизий.
- **Просмотр различий (Diff View)** — Появляется, когда у плана есть несколько ревизий (`revisionCount > 1`), предоставляя параллельное (side-by-side) или объединенное (unified) сравнение различий между ревизиями.
- **Рекомендации** — Содержит список проактивных [Рекомендаций](07_Recommendations.md), сгенерированных для этого плана, со встроенными элементами управления сортировкой Accept и Decline.
- **Git** — Появляется, как только создаются артефакты выполнения. Отслеживает активные рабочие деревья (worktrees) [Git](https://git-scm.com), записанные коммиты, ссылки на PR (см. [Pull Requests](06_PullRequests.md)) и предупреждает о риске потери неслитых коммитов с возможностью синхронизации рабочих деревьев с удаленными репозиториями.

### Панели и чат

- **Панель верификаций** — Доступная из выпадающего меню в правом верхнем углу, эта панель отображает настроенные рубежи [Верификации](../03_Configuration/01_Setup.md#verifications) (`Build`, `Test`, `Lint` и т. д.) с их статусом прохождения в реальном времени и логами вывода.
- **Чат плана** — Встроенная панель интерактивного чата (`PlanChatPanel`) для мозгового штурма, уточнения подхода или вопросов агенту по плану перед запуском изменений в коде.

## Действия Promptware

См. раздел [Promptwares](../02_Concepts/02_Promptwares.md) для получения подробной информации о выполнении этих рабочих процессов:

| Действие             | Назначение                                                                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ExecutePlan**      | Фиксирует последнюю ревизию плана, создает изолированную ветку рабочего дерева [Git](https://git-scm.com) (worktree) и запускает [Агента написания кода](../06_CodingAgents/_Index.md) для реализации изменений. |
| **ExpandPlan**       | Запрашивает у агента развертывание краткого описания в структурированный план с подробными шагами, целевыми файлами и планами тестирования.                                                                      |
| **SplitPlan**        | Разделяет большой или сложный план на более мелкие, сфокусированные подпланы, которые могут выполняться независимо.                                                                                              |
| **Shelve to Icebox** | Перемещает план в [Хранилище идей (Icebox)](05_Icebox.md), чтобы разгрузить активную очередь с сохранением всего контекста.                                                                                      |
| **Delete Plan**      | Запрашивает подтверждение для безвозвратного удаления папки плана и связанных записей.                                                                                                                           |

## Файлы на диске и синхронизация в реальном времени

Каждый план поддерживается директорией по пути `$TENDRIL_HOME/plans/<planId>/`:

- `plan.yaml` — Метаданные плана в формате [YAML](https://yaml.org), состояние, привязка к проекту и записи верификации. См. [CLI Plan](../09_Advanced/01_CLI/01_Plan.md).
- `revisions/` — Версионированные файлы markdown (`001.md`, `002.md` и т. д.), представляющие каждую итерацию спецификации.
- `costs.csv` — Журнал учета токенов и затрат, работающий только на добавление (append-only).

Tendril использует механизмы отслеживания файловой системы для обнаружения изменений, сделанных во внешних текстовых редакторах или IDE, мгновенно обновляя интерфейс без необходимости ручной перезагрузки.
