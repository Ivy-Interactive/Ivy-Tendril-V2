# Рекомендации

Приложение «Рекомендации» — это центр сортировки и обработки Tendril для предлагаемых ИИ улучшений кодовой базы, расширения тестового покрытия, архитектурной очистки и устранения технического долга, обнаруженных во время выполнения планов.

## Источники и условия доступности

Когда [Coding Agents](../06_CodingAgents/_Index.md) анализируют, выполняют и верифицируют планы, они выявляют сопутствующие улучшения (например, непротестированные граничные случаи, устаревшие зависимости, возможности для рефакторинга или узкие места в производительности).

Чтобы рекомендации оставались практически применимыми и во избежание преждевременной работы:

- В приложении «Рекомендации» отображаются только рекомендации, полученные из планов со статусом **Completed** (см. [Plan Lifecycle](../02_Concepts/03_Lifecycle.md)).
- Рекомендации из завершившихся сбоем или выполняющихся планов остаются привязанными к исходному плану до тех пор, пока этот план не завершится успешно.

## Очередь рекомендаций

На боковой панели представлены все ожидающие обработки рекомендации:

- **Тег исходного плана** — отображает номер исходного плана (например, `#14`).
- **Заголовок** — краткое описание предлагаемого улучшения.
- **Бейдж проекта** — указывает, на какой репозиторий проекта нацелена рекомендация (настраивается в [Project Setup](../03_Configuration/02_Projects.md)).
- **Бейдж влияния (Impact)** — цветовая оценка срочности и ценности:
  - `High` (зеленый) — критические исправления, значительный рефакторинг или существенные пробелы в тестах.
  - `Medium` (янтарный) — наведение порядка, улучшения поддержки кода или неблокирующие доработки.
  - `Low` (нейтральный) — незначительные правки или косметические улучшения.

## Подробный просмотр и действия по сортировке

При выборе рекомендации отображается ее полное техническое обоснование, оценка влияния и ссылка для открытия исходного плана (**Source Plan**) в [Plans](03_Plans.md).

Разработчики могут сортировать рекомендации с помощью четырех основных действий:

| Действие                | Элемент управления      | Результат                                                                                                                                                                                                                          |
| ----------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Accept**              | Кнопка CircleCheck      | Помечает рекомендацию как `Accepted` и немедленно запускает фоновый [Job](04_Jobs.md) `CreatePlan` (см. [Promptwares](../02_Concepts/02_Promptwares.md)) для создания черновика новой реализации в [Plans](03_Plans.md).           |
| **Accept with Notes**   | Кнопка Check            | Открывает `RecommendationNoteDialog`, позволяя разработчику добавить конкретные ограничения или требования. Агент получает как исходную рекомендацию, так и заметки оператора.                                                     |
| **Decline**             | Кнопка X                | Помечает рекомендацию как `Declined` с возможностью указать причину отклонения и удаляет ее из очереди ожидания.                                                                                                                   |
| **Create GitHub Issue** | Кнопка с иконкой GitHub | Открывает `CreateIssueDialog` для создания issue по этой рекомендации напрямую в [GitHub](https://github.com) через [GitHub CLI](https://cli.github.com) (`gh`) в репозитории проекта. Оставляет рекомендацию в статусе `Pending`. |

После завершения действия Tendril автоматически переходит к следующей рекомендации в очереди, обеспечивая быстрый просмотр предложенных улучшений.
