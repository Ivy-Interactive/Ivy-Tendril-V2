# Руководство

Это полное сквозное практическое руководство на примере любого репозитория по вашему выбору. Оно охватывает регистрацию проекта,
создание плана, внесение изменений в изолированных рабочих деревьях (worktrees), проверку диффов и создание pull request.

## Шаг 1: Сборка и проверка

Следуйте инструкциям из раздела [Установка](02_Installation.md), чтобы установить или собрать Tendril и добавить `tendril` в `PATH`.
Проверьте корректность окружения:

```bash
tendril doctor
```

`tendril doctor` проверяет `$TENDRIL_HOME`, `config.yaml`, базу данных [SQLite](https://www.sqlite.org),
каталог планов, [Git](https://git-scm.com/) и [GitHub CLI](https://cli.github.com/) (`gh`). Устраните все пункты
со статусом `[FAIL]` перед тем, как продолжить.

## Шаг 2: Запуск Tendril

Запустите десктопное приложение:

```bash
pnpm dev:desktop
```

Десктопное приложение запустится и автоматически поднимет фонового демона `tendril run`. Демон
предоставляет REST и WebSocket API, через которые взаимодействуют интерфейс приложения и CLI.

Если вы предпочитаете запускать демон в автономном (headless) режиме:

```bash
# Проверяет порт и запускает ожидающие миграции
tendril run

# Или прямой слушатель с пользовательскими параметрами:
tendril serve --host 127.0.0.1 --port 5010
```

## Шаг 3: Регистрация вашего репозитория

Для работы Tendril требуется локальный репозиторий git:

```bash
git clone https://github.com/your-org/your-repo.git
```

Зарегистрируйте проект через десктопное приложение в меню **Settings → Projects** или с помощью CLI:

```bash
tendril project add MyProject
tendril project add-repo MyProject /Users/you/Repos/MyProject
tendril project add-verification MyProject CheckResult
```

Оба способа обновляют `$TENDRIL_HOME/config.yaml`, который вы также можете отредактировать вручную:

```yaml
codingAgent: claude

projects:
  - name: MyProject
    repos:
      - path: /Users/you/Repos/MyProject
    verifications:
      - name: NpmBuild
        required: true
      - name: CheckResult
        required: true
```

Укажите в качестве `codingAgent` установленного у вас агента:

- [Claude Code](https://code.claude.com/docs) (`claude`)
- [OpenAI Codex](https://openai.com) (`codex`)
- [GitHub Copilot](https://github.com/features/copilot) (`copilot`)
- [Google Gemini](https://ai.google.dev) (`gemini`)
- [OpenCode](https://opencode.ai) (`opencode`)
- Antigravity (`antigravity` / `agy`)
- [Cursor](https://www.cursor.com) (`cursor`)
- Apple Foundation Models (`apple` через локальный `fm`)

> [!TIP]
> Добавьте файл `AGENTS.md` в корень вашего репозитория с описанием архитектурных соглашений и команд сборки.
> Tendril внедряет его в системный контекст агента при каждом запуске. См. рекомендации в разделе
> [Подключение кодовой базы](03_Onboarding.md).

## Шаг 4: Создание плана

Нажмите **New Plan** в десктопном приложении и укажите описание задачи. Tendril запустит
агента рабочего процесса [CreatePlan](../02_Concepts/02_Promptwares.md), который сформирует структурированный
план, содержащий формулировку проблемы, поэтапное решение и критерии верификации.

Вы также можете создать план из CLI:

```bash
tendril plan create "Add a health-check endpoint" MyProject
```

План перейдёт в состояние **Draft** (Черновик). Откройте черновик плана, чтобы изучить предложенную спецификацию. Вы можете добавлять
текстовые аннотации прямо в интерфейсе, чтобы скорректировать масштаб задачи или добавить ограничения, побуждая
[UpdatePlan](../02_Concepts/02_Promptwares.md) объединить ваши замечания в
обновлённую ревизию.

## Шаг 5: Выполнение плана

Когда черновик будет готов, нажмите **Execute** (или выполните команду `tendril plan execute <plan-id>`).
Агент [ExecutePlan](../02_Concepts/02_Promptwares.md):

1. создаёт изолированное [рабочее дерево Git (worktree)](https://git-scm.com/docs/git-worktree) по пути `Worktrees/{repo-name}/`,
   оставляя вашу основную ветку нетронутой;
2. загружает спецификацию плана, контекст репозитория и заметки памяти;
3. фаза за фазой реализует изменения в коде с пошаговыми коммитами git;
4. запускает каждый настроенный этап верификации (сборка, линтинг, тесты, скриншоты).

Отслеживайте ход выполнения в реальном времени в представлении **Jobs** десктопного приложения или через CLI:

```bash
tendril job list          # просмотр статусов заданий
tendril job queue         # проверка очереди отправки
```

Когда все фазы будут завершены и обязательные проверки пройдены, план перейдёт в состояние **Review**.

> [!NOTE]
> Если этап верификации завершился ошибкой, план переходит в статус **Failed**, а рабочее дерево сохраняется на диске. Изучите
> отчёт об ошибке в папке `Verification/` или запустите
> [RetryPlan](../02_Concepts/02_Promptwares.md), чтобы агент попытался исправить проблему.

## Шаг 6: Проверка результата

Перейдите на экран **Review** для проверки проделанной работы:

- **Git Diff** — просмотр подсвеченных диффов для всех затронутых файлов;
- **Verification Reports** — отчёты автоматических сборок и тестов;
- **Execution Transcripts** — логи вызовов инструментов, потоки stdout/stderr и расход токенов;
- **Follow-up Recommendations** — рекомендации по техническому долгу или улучшениям, отмеченным агентом.

Одобрите план, когда результат вас удовлетворит. Tendril запустит
[CreatePr](../02_Concepts/02_Promptwares.md) для создания pull request через
[GitHub CLI](https://cli.github.com/) (`gh`), переводя план в состояние **Completed**.

## Что произошло

Вы только что завершили стандартный цикл разработки Tendril:

```
Draft → Creating → Executing → Review → Completed
```

Автономный агент работал в изолированном рабочем дереве, успешно прошёл проверки верификации и сформировал
проверенный pull request, сохранив все промпты, диффы и расходы в папке `$TENDRIL_HOME/Plans/`.
