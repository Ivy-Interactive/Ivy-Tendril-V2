# Получение помощи

Если у вас возникли проблемы или вопросы по настройке Tendril, вам доступны различные ресурсы поддержки и
диагностические инструменты.

## Сначала запустите диагностику

Перед отправкой issue или обращением за помощью запустите встроенную диагностику окружения Tendril:

```bash
tendril doctor
```

`tendril doctor` проверяет каталог `$TENDRIL_HOME`, синтаксис `config.yaml`, доступность базы данных
[SQLite](https://www.sqlite.org), каталог [планов](../02_Concepts/01_Plans.md), [Git](https://git-scm.com/) и
авторизацию в [GitHub CLI](https://cli.github.com/).

Если завершился ошибкой конкретный план или задание, вы можете собрать полный диагностический пакет с помощью `tendril report-bug`:

```bash
# Упаковка состояния плана, отчётов верификации и логов заданий в zip-архив
tendril report-bug <plan-id>
```

Команда формирует диагностический архив, содержащий YAML-файл плана, историю ревизий, результаты верификации
и исходные транскрипты агента без раскрытия конфиденциальных данных.

## Устранение неполадок

С описанием типичных сообщений об ошибках, миграций базы данных и восстановления рабочих деревьев можно ознакомиться в разделе
[Устранение неполадок](06_Troubleshooting.md).

## Сообщество в Discord

Самый быстрый способ связаться с командой разработчиков и другими пользователями — наш
[сервер Discord](https://discord.gg/FHgxkDga3y). Присоединяйтесь, чтобы задавать вопросы, делиться отзывами и обсуждать собственные
рабочие процессы промптваров.

## Задачи на GitHub (Issues)

Нашли ошибку или хотите предложить новую функцию? Создайте issue в нашем
[репозитории GitHub](https://github.com/Ivy-Interactive/Ivy-Tendril-V2/issues).

> [!TIP]
> Всегда прикрепляйте вывод команд `tendril doctor` и `tendril version` к описанию вашей проблемы. Если вы
> сообщаете о неудачном выполнении плана, приложите диагностический zip-архив, созданный с помощью `tendril report-bug <plan-id>`,
> или лог задания из `$TENDRIL_HOME/Jobs/`.
