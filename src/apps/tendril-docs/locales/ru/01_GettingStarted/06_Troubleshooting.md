# Устранение неполадок

Диагностика и решение типичных проблем с конфигурацией, агентами, планами и базой данных.

## Установка и окружение

| Симптом                                          | Решение                                                                                                                                                                                                        |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TENDRIL_HOME` не найден                         | Задайте переменную окружения и перезапустите терминал либо запишите путь в `~/.tendril_location`. Без них Tendril использует путь по умолчанию: `~/.tendril`.                                                  |
| `config.yaml` не найден                          | Файл должен находиться по пути `$TENDRIL_HOME/config.yaml` и называться именно так — не `tendril-config.yaml`. Команда `tendril doctor` сообщает ожидаемый путь.                                               |
| `gh` не авторизован                              | Выполните авторизацию в [GitHub CLI](https://cli.github.com/): `gh auth login`, затем проверьте статус командой `gh auth status`.                                                                              |
| `git` не найден                                  | Установите [Git](https://git-scm.com/) и убедитесь, что он доступен в вашем `PATH`.                                                                                                                            |
| `tendril` не распознаётся после сборки           | `cargo build --release` оставляет бинарный файл в `target/release/tendril`. Добавьте этот путь в `PATH` или выполните `cargo install --path src/crates/tendril-cli`.                                           |
| Приложение запускается, но ничего не загружается | Десктопное приложение управляет демоном `tendril run`; если бинарные файлы sidecar отсутствуют в собранном пакете, приложению не с чем взаимодействовать. См. шаги упаковки в [Установке](02_Installation.md). |

## Планы

| Симптом                                 | Решение                                                                                                                                                                        |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| План завис в статусе `Draft`            | Убедитесь, что репозиторий прикреплён, с помощью `tendril plan get <id>`, и проверьте наличие определения проекта в файле `config.yaml`.                                       |
| Папка плана неполная или не загружается | Выполните `tendril plan validate <id>` для поиска ошибок — некорректный `plan.yaml`, отсутствующая папка `Revisions/`, пустой заголовок или несовпадение версий схемы.         |
| План использует устаревшую схему        | Выполните `tendril plan doctor --fix`, чтобы перенести папки планов на текущую схему. Чтобы удалить пустые оболочки-сироты, выполните `tendril plan doctor --prune-husks`.     |
| У плана не настроены репозитории        | Выполните команду `tendril plan add-repo <id> <path>`.                                                                                                                         |
| Устаревшее рабочее дерево после сбоя    | Выполните `tendril plan cleanup <id>`, чтобы удалить рабочие деревья завершённых планов. Для незавершённых планов укажите флаг `--force`: `tendril plan cleanup <id> --force`. |

## Выполнение и агенты

| Симптом                            | Решение                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Агент недоступен                   | Проверьте параметр `codingAgent` в `config.yaml`, затем запустите CLI агента напрямую в чистом терминале. Tendril запускает его как дочерний процесс; если `claude`, `codex`, `copilot`, `gemini`, `opencode`, `antigravity` или `cursor` не могут работать автономно, фоновые задания зависнут. Для `apple` проверьте `fm available` и убедитесь, что `fm serve` активен. |
| Выполнение завершается сбоем сразу | Проверьте лог задания в `$TENDRIL_HOME/Jobs/{jobId}-{planId}-{promptware}/`. Типичные причины — отсутствие контекста репозитория или недостаток прав инструментов в [Промптварах](../02_Concepts/02_Promptwares.md).                                                                                                                                                       |
| Верификация постоянно даёт сбой    | Запустите команду верификации вручную внутри изолированного рабочего дерева плана (`$TENDRIL_HOME/Plans/{id}-{name}/Worktrees/{repo}`). Обычно команда корректна, но в рабочем дереве пропущен шаг настройки — см. [Подключение кодовой базы](03_Onboarding.md).                                                                                                           |
| Задание никогда не запускается     | Выполните `tendril job queue`, чтобы проверить порядок отправки и лимиты параллелизма (`maxConcurrentJobs` в `config.yaml`). Повысьте приоритет задания с помощью `tendril job force-start <id>` или остановите зависшие задания через `tendril job stop-all`. См. [Жизненный цикл и задания](../02_Concepts/03_Lifecycle.md).                                             |
| Голосовой ввод недоступен          | В macOS предоставьте разрешения микрофону в System Settings → Privacy & Security → Microphone, затем перезапустите десктопное приложение.                                                                                                                                                                                                                                  |

## База данных

Tendril управляет базой данных [SQLite](https://www.sqlite.org) в `$TENDRIL_HOME/tendril.db`. Хотя миграции
выполняются автоматически при запуске демона, Tendril предоставляет специальные команды управления базой данных:

```bash
# Проверить текущую версию схемы базы данных
tendril db version

# Применить ожидающие миграции
tendril db migrate

# Проверить целостность базы данных
tendril db integrity

# Освободить неиспользуемое дисковое пространство
tendril db vacuum

# Сбросить базу данных (требуется подтверждение)
tendril db reset
```

| Симптом                              | Решение                                                                                                                                                                                                                                 |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Не уверены в исправности базы данных | Выполните `tendril doctor` (проверяет подключение) или `tendril db integrity` для проверки внутренней целостности SQLite.                                                                                                               |
| База данных заблокирована            | Другой процесс удерживает эксклюзивную блокировку. Одновременно должен быть запущен только один демон; закройте десктопное приложение перед ручным запуском `tendril run` или `tendril serve`.                                          |
| База данных повреждена               | Остановите приложение и демон, затем выполните `tendril db reset` (или удалите `$TENDRIL_HOME/tendril.db` вместе с файлами `-wal` и `-shm`). Файлы планов в формате Markdown в `$TENDRIL_HOME/Plans/` сохранятся полностью нетронутыми. |

> При запросе помощи в [Discord](https://discord.gg/FHgxkDga3y) или GitHub соберите полный пакет диагностических
> логов с помощью команды `tendril report-bug <plan-id>` — см. [Получение помощи](05_GettingHelp.md).
