# Подключение кодовой базы

Tendril запускает кодинг-агента для вашего репозитория внутри изолированного
[рабочего дерева Git (worktree)](https://git-scm.com/docs/git-worktree), затем выполняет сборку, тестирование и открывает pull request.
Чтобы этот цикл успешно завершался без вмешательства человека, систему и репозиторий необходимо настроить
заранее. Пройдите по приведённому ниже чек-листу один раз для компьютера и один раз для каждой кодовой базы.

> [!TIP]
> По завершении выполните `tendril doctor`. Команда проверяет рабочую директорию Tendril, файл `config.yaml`, базу данных,
> каталог планов, `git` и `gh`. Она **не** тестирует кодинг-агента — проверьте его самостоятельно с помощью
> шага 2 ниже.

## Чек-лист для компьютера

### 1. Установлено необходимое ПО для сборки

Все инструменты, необходимые для компиляции проекта, должны быть установлены и доступны в `PATH`. Агент не сможет
установить недостающий компилятор или SDK посреди выполнения задания. Для репозитория на Rust и pnpm (такого как сам Tendril)
это означает [Rustup](https://rustup.rs/), [Node.js](https://nodejs.org/) и [pnpm](https://pnpm.io/); для вашего
проекта — любой тулчейн сборки, вызываемый вашими скриптами.

> [!NOTE]
> Основное требование: свежеклонированный репозиторий должен собираться из чистого терминала с помощью документированных команд,
> без интерактивных запросов и без ручных действий, доступных только в IDE.

### 2. Предпочитаемый CLI кодинг-агента установлен и авторизован

Установите агента, указанного как `codingAgent` в `config.yaml`, и выполните вход в систему, чтобы он работал неинтерактивно:

```bash
# Пример: Claude Code
npm install -g @anthropic-ai/claude-code
claude login
```

Убедитесь, что CLI доступен в `PATH` и обычный вызов не останавливается для запроса учётных данных:

- [Claude Code](https://code.claude.com/docs) (`claude`)
- [OpenAI Codex](https://openai.com) (`codex`)
- [GitHub Copilot](https://github.com/features/copilot) (`copilot`)
- [Google Gemini](https://ai.google.dev) (`gemini`)
- [OpenCode](https://opencode.ai) (`opencode`)
- Antigravity (`antigravity` / `agy`)
- [Cursor](https://www.cursor.com) (`cursor` / `cursor-agent`)
- Apple Foundation Models (`apple` через локальный `fm`)

Агент `apple` является исключением: он работает через встроенный OpenCode с локальной моделью Apple на устройстве,
поэтому убедитесь, что утилита `fm` установлена (проверьте с помощью `fm available`) и процесс `fm serve` уже запущен и слушает запросы.

### 3. Git установлен и настроен для автономной работы

Tendril клонирует код, создаёт рабочие деревья, делает коммиты и пушит изменения от вашего имени. Убедитесь, что все операции работают
без интерактивных запросов:

- Настроены глобальные имя и email (`git config --global user.name` и `user.email`).
- Учётные данные сохранены через помощник учётных данных (credential helper) или SSH-ключ загружен в ssh-agent, благодаря чему `git pull` и
  `git push` никогда не запрашивают пароль.
- Рабочие деревья успешно создаются и удаляются (`git worktree add` и `git worktree remove`).

> [!WARNING]
> Если при отправке изменений по HTTPS запрашиваются учётные данные, настройте credential helper или используйте SSH-ключ с
> активным `ssh-agent`. Один интерактивный запрос остановит выполнение фонового задания.

### 4. GitHub CLI установлен и авторизован

[CreatePr](../02_Concepts/02_Promptwares.md) использует [GitHub CLI](https://cli.github.com/)
(`gh`) для создания pull request. Установите его и проверьте авторизацию:

```bash
gh auth login
gh auth status
```

### 5. Необходимые серверы MCP установлены глобально

Если вы используете серверы [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) — например, Jira
для контекста задач или Figma для макетов интерфейса — установите и зарегистрируйте их глобально, чтобы каждое рабочее дерево имело к ним
доступ. Серверы MCP регистрируются в кодинг-агенте, а не внутри Tendril:

```bash
# Пример: глобальная регистрация сервера MCP для Claude Code
claude mcp add --scope user jira -- npx -y @your-org/jira-mcp
claude mcp add --scope user figma -- npx -y figma-developer-mcp
claude mcp list   # проверка доступности
```

> [!NOTE]
> Используйте глобальную область видимости (scope: user), а не проектную, чтобы серверы MCP оставались доступными в эфемерных рабочих деревьях git,
> в которых работает агент. Необходимые токены API сохраняйте в переменных окружения вашей системы.

Убедитесь, что вы действительно _авторизованы_ на каждом MCP-сервере, а не просто зарегистрировали его. Выполните
небольшой тестовый план в Tendril и убедитесь, что каждый сервер инициализируется без всплывающих окон OAuth.

## Чек-лист для репозитория

### 6. Репозиторий готов к работе с Git worktrees

[ExecutePlan](../02_Concepts/02_Promptwares.md) запускается внутри изолированного
[рабочего дерева Git](https://git-scm.com/docs/git-worktree), а не в вашей текущей рабочей директории. Рабочее дерево создаётся
из чистого коммита — в нём нет папок `target/`, `node_modules/` или неотслеживаемых файлов `.env`.

- Документируйте все команды настройки, необходимые после клонирования перед сборкой (например, восстановление зависимостей,
  генерация кода, копирование шаблонного `.env`), и добавьте зафиксированный в git установочный скрипт.
- Не полагайтесь на незакоммиченные файлы, существующие только в вашем основном рабочем каталоге.
- Используйте пакетный менеджер с централизованным кэшем, чтобы каждое рабочее дерево инициализировалось за секунды вместо
  повторной загрузки пакетов (например, хранилище pnpm, кэш реестра Cargo или кэш модулей Go).

> [!TIP]
> Быстрая проверка: выполните `git worktree add ../repo-probe`, затем запустите документированные команды сборки в этой
> директории из чистого терминала. Если проект компилируется и проходит тесты, Tendril также справится успешно. Удалите временную директорию с помощью
> `git worktree remove ../repo-probe`.

### 7. Создайте скрипт запуска для каждого приложения

Добавьте небольшой закоммиченный скрипт запуска для каждого приложения в репозитории с возможностью настройки портов через переменные.
Tendril может выполнять параллельные планы одновременно в нескольких рабочих деревьях, поэтому жёстко заданные порты приведут к конфликтам.

Для фронтенда на [Vite](https://vite.dev) в связке с API на Python скрипт может выглядеть так:

```bash
#!/usr/bin/env bash
# run.sh - запуск бэкенда на Python и фронтенда на Vite
set -euo pipefail

api_port="${API_PORT:-8000}"
web_port="${WEB_PORT:-5173}"

cd "$(dirname "$0")"

# Бэкенд: настройка virtualenv и установка зависимостей
python -m venv .venv
source .venv/bin/activate
pip install -q -r requirements.txt

# Запуск API бэкенда на выделенном порту
uvicorn app.main:app --port "$api_port" &
api_pid=$!

# Завершение бэкенда при выходе из процесса фронтенда
trap 'kill "$api_pid" 2>/dev/null' EXIT

# Фронтенд: установка зависимостей и запуск сервера разработки Vite
npm --prefix web install --prefer-offline --no-audit
npm --prefix web run dev -- --port "$web_port" --open
```

> [!NOTE]
> Наличие команд запуска в версионируемом скрипте гарантирует, что как разработчики, так и автономные агенты
> запускают приложение одинаковым образом.

### 8. Добавьте AGENTS.md (или README.md) в корень репозитория

Предоставьте агентам базовый контекст, необходимый для навигации по кодовой базе без догадок:

- **Предварительные требования**, необходимые для сборки и запуска кода.
- **Архитектурная карта** с описанием приложений, библиотек и протоколов взаимодействия.
- **Команды сборки и тестирования**, компилирующие и проверяющие репозиторий.
- **Скрипты запуска**, ссылающиеся на скрипты из предыдущего шага.
