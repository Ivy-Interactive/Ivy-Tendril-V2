# Жизненный цикл и задания

Каждый раз, когда Tendril выполняет действие от вашего имени, он создаёт **задание (job)**: один запуск одного
[агента рабочего процесса (промптвара)](02_Promptwares.md) для одного [плана](01_Plans.md). С помощью заданий план
перемещается по своему жизненному циклу, и именно их вы наблюдаете в реальном времени в десктопном приложении и CLI.

## Статусы заданий

| Статус        | Значение                                                                |
| ------------- | ----------------------------------------------------------------------- |
| **Pending**   | Создано, но ещё не помещено в очередь.                                  |
| **Queued**    | Ожидает доступного слота параллельного выполнения.                      |
| **Running**   | Процесс кодинг-агента активно выполняется.                              |
| **Completed** | Успешно завершено и прошло все обязательные проверки.                   |
| **Failed**    | Агент завершился с ошибкой или не пройдены обязательные верификации.    |
| **Timeout**   | Превышен установленный лимит времени выполнения, процесс остановлен.    |
| **Stopped**   | Остановлено действием пользователя.                                     |
| **Blocked**   | Не может продолжаться — ожидает зависимого задания, данных или решения. |

## Цикл выполнения

1. **Очередь (Queue)** — задание создаётся и ставится в очередь за текущими выполняемыми задачами.
2. **Подготовка (Prepare)** — для промптваров, изменяющих код ([ExecutePlan](02_Promptwares.md),
   [RetryPlan](02_Promptwares.md)), Tendril подготавливает изолированное
   [рабочее дерево Git (worktree)](https://git-scm.com/docs/git-worktree) для каждого репозитория в папке
   `Worktrees/{repo-name}/` плана. Выполнение никогда не затрагивает и не блокирует ваш основной рабочий каталог.
3. **Реализация (Implement)** — агент рабочего процесса поэтапно реализует фазы плана, создавая коммиты.
4. **Верификация (Verify)** — каждый настроенный этап верификации выполняется в рабочем дереве и сохраняет результат.
5. **Отчёт (Report)** — логи вывода, расход токенов и обновлённое состояние плана записываются на диск и передаются демону.

Остановка задания возвращает план в состояние, в котором он находился до запуска задания, сохраняя при этом
содержимое рабочего дерева для анализа промежуточных результатов. Полная таблица состояний приведена в разделе [Планы](01_Plans.md).

## Верификации

Верификация — это автоматический рубеж контроля качества, указанный в `plan.yaml`. Каждая проверка выдаёт результат —
`Pass`, `Fail` или `Skipped` — вместе с подробным отчётом в папке `Verification/` плана.
То, какие проверки запускаются, зависит от изменяемых планом файлов:

| Верификация     | Что проверяется                                                    |
| --------------- | ------------------------------------------------------------------ |
| **NpmBuild**    | Рабочая область pnpm / npm собирается без ошибок.                  |
| **NpmLint**     | Линтинг и форматирование пакетов TypeScript / JavaScript пройдены. |
| **NpmTest**     | Наборы автотестов успешно пройдены (Vitest, Jest и др.).           |
| **RustBuild**   | Пакеты Cargo компилируются без ошибок.                             |
| **RustClippy**  | Линтер Clippy не выдаёт предупреждений или ошибок.                 |
| **RustFormat**  | Проверка `cargo fmt --check` подтверждает единый стиль.            |
| **RustTest**    | Модульные и интеграционные тесты Rust успешно пройдены.            |
| **Screenshots** | Собраны визуальные подтверждения для изменений интерфейса.         |
| **CheckResult** | Собственное подтверждение агента о выполнении критериев плана.     |

Верификация, которая не относится к плану, помечается как `Skipped`, а не просто опускается,
что обеспечивает непрерывную историю аудита. План переходит в статус **Review** только тогда, когда все обязательные проверки пройдены.
Если проверка не удалась, план переходит в статус **Failed**, и
[RetryPlan](02_Promptwares.md) может выполнить ещё один проход с точным текстом ошибки
и текущим диффом в контексте.

> [!TIP]
> При сбое верификации изучите отчёт в `Verification/` и выполните команду вручную в рабочем дереве
> плана. Обычно команда верна, а в рабочем дереве просто пропущен шаг настройки — см.
> [Подключение кодовой базы](../01_GettingStarted/03_Onboarding.md).

## Параллелизм и рабочие деревья

Несколько заданий могут выполняться одновременно под управлением параметра `maxConcurrentJobs` в
[~/.tendril/config.yaml](../03_Configuration/01_Setup.md) (по умолчанию `20`):

```yaml
maxConcurrentJobs: 4
```

Поскольку каждый выполняемый план работает внутри выделенных [рабочих деревьев git](https://git-scm.com/docs/git-worktree),
параллельные задания в одном репозитории не конфликтуют. Тем не менее, параллельные запуски разделяют ресурсы процессора, оперативной памяти
и лимиты запросов к API кодинг-агентов, поэтому настройте `maxConcurrentJobs` под вашу рабочую станцию.

## Отслеживание затрат

Каждый запуск фиксирует потраченные токены и ориентировочную стоимость в долларах. Постоянным журналом аудита служит
файл `costs.csv` плана, куда добавляется одна строка на каждый запуск:

```csv
Promptware,Tokens,Cost,Model,CostSource,Agent
ExecutePlan,148213,1.9042,claude-opus-5,api,claude
```

Если агент работает по безлимитной подписке (или на локальной модели, такой как Apple Foundation Models),
поле `Cost` остаётся пустым, а не нулевым, сохраняя метрики токенов без выдумывания денежных сумм.

## Управление заданиями и их мониторинг

Десктопное приложение отображает текущий статус заданий и потоковый вывод терминала через WebSocket-поток
демона. Интерфейс командной строки (CLI) обеспечивает полную эквивалентность:

```bash
# Список всех активных и недавних заданий
tendril job list

# Фильтрация заданий по статусу
tendril job list --status Running
tendril job list --status Failed

# Проверка очереди отправки и доступных слотов
tendril job queue

# Немедленный принудительный запуск задания из очереди
tendril job force-start <job-id>

# Отмена выполняемого задания
tendril job cancel <job-id> -m "Stopping for review"

# Остановка всех выполняемых, находящихся в очереди и заблокированных заданий
tendril job stop-all

# Удаление завершённых или сбойных заданий из базы данных
tendril job clear --completed
tendril job clear --failed
```

Полные логи и транскрипты каждого запуска сохраняются на диске по пути
`$TENDRIL_HOME/Jobs/{jobId}-{planId}-{promptware}/`, включая исходный системный промпт,
трассировку вызовов инструментов и стенограмму ответов агента.
