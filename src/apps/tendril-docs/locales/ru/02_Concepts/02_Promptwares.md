# Промптвары

Промптвар (promptware) — это каталог, содержащий инструкции, инструменты и память, определяющие узкоспециализированного
агента рабочего процесса. Развёрнутые копии находятся в `$TENDRIL_HOME/Promptwares/`, по одной папке на каждый промптвар:

- **Program.md** — системный промпт: цель агента, пошаговый алгоритм и правила выполнения.
- **Tools/** — исполняемые скрипты и утилиты, которые агент может вызывать во время работы.
- **Memory/** — сохраняемые заметки в формате Markdown, которые живут между запусками. Эта обратная связь позволяет
  промптварам изучать особенности кодовой базы и совершенствоваться вместо повторения одних и тех же ошибок.

Tendril отправляет промптвары через настроенного кодинг-агента (такого как
[Claude Code](../06_CodingAgents/01_ClaudeCode.md), [Codex](../06_CodingAgents/02_Codex.md),
[Copilot](../06_CodingAgents/03_Copilot.md), [Gemini](../06_CodingAgents/05_Gemini.md),
[OpenCode](../06_CodingAgents/04_OpenCode.md), Antigravity или [Cursor](https://www.cursor.com)), выполняя
по одному заданию за раз с предоставлением минимально необходимых прав доступа к инструментам (least-privilege).

## Развёртывание и слои

Tendril поставляется со стандартным набором встроенных промптваров. Команды также могут настроить каталог наложения
(overlay) в файле [config.yaml](../03_Configuration/01_Setup.md), чтобы переопределять системные промпты или предоставлять
собственные командные инструменты.

Развёртывание или обновление промптваров:

```bash
tendril promptware deploy
```

Чтобы проверить, запущен ли промптвар из базовой поставки или из наложения команды:

```bash
tendril promptware layers
# или проверить конкретный промптвар:
tendril promptware layers ExecutePlan
```

## Основные агенты рабочих процессов

| Промптвар        | Назначение                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| **CreatePlan**   | Составление плана по краткому описанию, элементу входящих или задаче [GitHub](https://github.com).           |
| **ExpandPlan**   | Дополнение лаконичного плана до реализуемой спецификации с фазами.                                           |
| **UpdatePlan**   | Обновление существующего плана на основе отзывов ревьюера, чата и встроенных аннотаций.                      |
| **SplitPlan**    | Разделение крупного плана на более мелкие независимые подпланы.                                              |
| **ExecutePlan**  | Создание изолированных [worktrees git](https://git-scm.com/docs/git-worktree), реализация фаз, тесты.        |
| **RetryPlan**    | Повторная попытка реализации плана, не прошедшего верификацию, с использованием логов и диффов.              |
| **CreatePr**     | Открытие pull request в GitHub по диффам рабочего дерева через [GitHub CLI](https://cli.github.com/) (`gh`). |
| **CreateIssue**  | Создание issue в GitHub в случае сбоя плана, изменения состояния или запроса триажа.                         |
| **AddProject**   | Регистрация нового проекта и настройка путей к его репозиториям.                                             |
| **SetupProject** | Определение и фиксация команд сборки, запуска и верификации проекта.                                         |
| **SyncRepo**     | Синхронизация репозиториев проекта с вышестоящими (upstream) ветками.                                        |

## Конфигурация

Каждый промптвар настраивается в файле [~/.tendril/config.yaml](../03_Configuration/01_Setup.md) в секции
`promptwares:`:

```yaml
promptwares:
  _default:
    profile: balanced

  CreatePlan:
    profile: deep
    allowedTools:
      - Read
      - Glob
      - Grep
      - Bash
      - Write(%PLANS_DIR%/**)
    deniedTools:
      - WebFetch
    customInstructions: |
      Always include acceptance criteria and verification gates in the plan.
```

| Поле                 | Обязательно | Описание                                                                                                                                                  |
| -------------------- | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `profile`            | Да          | Профиль агента: `quick`, `balanced` или `deep`. Профили определяют модель и уровень рассуждений (effort) для каждого агента.                              |
| `allowedTools`       | Нет         | Инструменты, предоставляемые сверх стандартных. Поддерживаются переменные `%PROMPTWARE_DIR%`, `%PLAN_DIR%` и `%PLANS_DIR%` для ограничения путей доступа. |
| `deniedTools`        | Нет         | Запрещённые инструменты (даже если они были бы разрешены другими правилами).                                                                              |
| `customInstructions` | Нет         | Произвольный текст, внедряемый в промпт агента с маркерами приоритетного переопределения.                                                                 |

Запись `_default` служит базовой конфигурацией для всех промптваров; именованная запись переопределяет её.

### Пользовательские инструкции (Custom instructions)

Если указано поле `customInstructions`, Tendril добавляет этот текст к скомпилированному промпту с явным
маркером приоритета. Агенту даётся указание следовать этим инструкциям в приоритете над базовым шаблоном и
собственным файлом `Program.md` промптвара. Используйте это для изменения поведения промптвара без редактирования общих
файлов программ.

## Порядок выполнения

1. **Контекст** — компиляция `Program.md`, прикрепление плана, встроенных аннотаций, настроек проекта и
   любых `customInstructions` из `config.yaml`.
2. **Инструменты и разрешения** — подключение папки `Tools/` и предоставление настроенных прав доступа с раскрытием
   переменных `%...%` в абсолютные пути. Доступные для записи каталоги строго ограничены папкой плана, папкой
   `Memory/` промптвара и рабочими деревьями git репозиториев.
3. **Запуск** — запуск кодинг-агента как фонового процесса задания в его изолированном рабочем дереве.
4. **Запись и телеметрия** — потоковая передача вывода в `$TENDRIL_HOME/Jobs/{jobId}-{planId}-{promptware}/`,
   отправка прогресса демону и фиксация расхода токенов и стоимости в файле `costs.csv` плана.

## Память и обучение

Память обеспечивает обратную связь: промптвар записывает то, что он узнал о проекте или характере сбоев,
и считывает эти данные при будущих запусках. CLI предоставляет прямое управление памятью:

```bash
# Список сохранённых заметок памяти для промптвара
tendril promptware list-memory ExecutePlan

# Чтение конкретной заметки памяти
tendril promptware read-memory ExecutePlan worktree-hygiene.md

# Запись или обновление заметки памяти из файла (или stdin)
tendril promptware write-memory ExecutePlan worktree-hygiene.md --file notes.md

# Удаление устаревшей или ошибочной заметки памяти
tendril promptware delete-memory ExecutePlan worktree-hygiene.md
```

> [!TIP]
> Память рассчитана как на расширение, так и на своевременную очистку: предположение или правило, ставшее неактуальным,
> следует удалять командой `delete-memory`, а не хоронить под противоречащими заметками.

## Прямой запуск

Для тестирования или запуска промптвара напрямую в интерактивном режиме в обход сервиса заданий демона:

```bash
# Прямой запуск CreatePlan с промптом задачи
tendril promptware run CreatePlan "Add a health-check endpoint" --profile deep

# Вывод скомпилированного системного промпта без запуска агента
tendril promptware run CreatePlan "Add a health-check endpoint" --dry-run
```
