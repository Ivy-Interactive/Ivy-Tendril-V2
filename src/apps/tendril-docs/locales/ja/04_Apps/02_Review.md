# レビュー

レビューアプリは Tendril の品質ゲートウェイです。エージェントが `ExecutePlan`（[プロンプトウェア](../02_Concepts/02_Promptwares.md) を参照）を介して計画の実行を完了すると、分離された [Git](https://git-scm.com) ワークツリーが保持され、開発者の検査、検証、およびトリアージのためにここに提示されます。操作者の明示的な承認なしにデフォルトブランチにマージされたり反映されたりすることはありません。

## レビューキュー

サイドバーには、開発者の対応が必要なすべての計画（`Review` または `Failed` ステータスの計画）が一覧表示されます：

- **バッジ** — 各行には、計画の `#ID`、プロジェクトバッジ、および [検証](../03_Configuration/01_Setup.md#verifications) ステータスが表示されます：
  - `Verified`（緑）— すべての必須検証ゲートに合格しました。
  - `Unverified`（警告）— 1 つ以上の検証ゲートが失敗したか、ゲートがまだ実行されていません。
  - トラブルシューティングが必要な実行を簡単に特定するための状態インジケーター（例：`Failed`）。
- **キーボードショートカット** — `ArrowLeft` および `ArrowRight` を使用して、レビューキュー内の計画を素早く切り替えます。

## レビューワークスペース

メインワークスペースには、計画の実装と検査ツールが表示されます：

- **計画の概要とコメント** — 計画の仕様を読み、行ごとの具体的なフィードバックを提供するためにインラインコメント（`DraftComment`）を残します。
- **レビューアクションバー** — プロジェクトで構成されたレビューアクション（[プロジェクト設定](../03_Configuration/02_Projects.md) の `reviewActions` で定義）がツールバーにワンクリックボタン（例：`Run E2E`、`Smoke Test`）としてレンダリングされます。
- **完全な仕様と差分を開く** — ワークスペースメニューからアクセスでき、[計画](03_Plans.md) 内の計画の完全な詳細ページを開いて、複数リビジョンの差分、Git ワークツリーコミットの到達可能性、および生成されたアーティファクトを検査します。
- **埋め込み計画チャット** — 統合された `PlanChatPanel` を使用して、承認前にエージェントに質問したり、実行ロジックを検査したり、実装の詳細を明確にしたりします。

## トリアージアクション

| アクション                  | コントロール                        | 効果                                                                                                                                                                                                     |
| --------------------------- | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Create Pull Request**     | プライマリ CTA                      | [GitHub CLI](https://cli.github.com)（`gh`）を介して [GitHub](https://github.com) プルリクエストを作成し、[プルリクエスト](06_PullRequests.md) で計画にリンクし、計画を `Completed` としてマークします。 |
| **Push to PR**              | プライマリ CTA（PR が存在する場合） | 新しいワークツリーのコミットを既存のプルリクエストブランチにプッシュします。                                                                                                                             |
| **Request Changes**         | アイコンボタン（バッジ付き）        | `SuggestChangesDialog` を開き、下書きコメントやフィードバックを送信して、既存のワークツリー内で `UpdatePlan` [ジョブ](04_Jobs.md) を起動します。                                                         |
| **Accept Partial Delivery** | セカンダリボタン                    | `PartialDeliveryDialog` を開き、残りの項目をステージングしながら、成果物の動作する部分を受け入れます。                                                                                                   |
| **Reset to Draft**          | オーバーフローメニュー              | `ResetToDraftDialog` を開き、計画を再スコープするために [計画](03_Plans.md) で `Draft` に戻します。                                                                                                      |
| **Delete Plan**             | オーバーフローメニュー（破壊的）    | `DeletePlanDialog` を開き、計画を完全に削除し、その分離されたワークツリーを破棄します。                                                                                                                  |
