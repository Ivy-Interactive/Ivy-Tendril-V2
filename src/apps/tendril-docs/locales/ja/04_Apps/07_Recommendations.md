# レコメンデーション

レコメンデーションアプリは、計画の実行中に発見された AI 提案によるコードベースの改善、テストカバレッジの追加、アーキテクチャの整理、および技術的負債項目のための Tendril のトリアージセンターです。

## ソースと適用資格

[コーディングエージェント](../06_CodingAgents/_Index.md) が計画を分析、実行、検証するにつれて、関連する改善点（未テストのエッジケース、非推奨の依存関係、リファクタリングの機会、パフォーマンスのボトルネックなど）が明らかになります。

レコメンデーションを実行可能な状態に保ち、時期尚早な作業を避けるために：

- **Completed**（完了）状態の計画から発信されたレコメンデーションのみがレコメンデーションアプリに表示されます（[計画ライフサイクル](../02_Concepts/03_Lifecycle.md) を参照）。
- 失敗した計画または実行中の計画から発信されたレコメンデーションは、その計画が成功するまでソース計画に紐付けられたままになります。

## レコメンデーションキュー

サイドバーには、すべての保留中のレコメンデーションが表示されます：

- **ソース計画タグ** — 元の計画番号（例：`#14`）を表示します。
- **タイトル** — 提案された改善の簡潔な説明。
- **プロジェクトバッジ** — レコメンデーションがどのプロジェクトリポジトリを対象としているかを識別します（[プロジェクト設定](../03_Configuration/02_Projects.md) で構成）。
- **影響バッジ** — 色分けされた緊急度と価値の評価：
  - `High`（緑）— 重要な修正、大幅なリファクタリング、または不可欠なテストギャップ。
  - `Medium`（黄）— クリーンアップ、保守性の向上、または非ブロッキングな機能強化。
  - `Low`（ニュートラル）— 軽微な推敲または外観の改善。

## 詳細ビューとトリアージアクション

レコメンデーションを選択すると、その完全な技術的根拠、影響評価、および [計画](03_Plans.md) で元の **ソース計画** を開くためのリンクが表示されます。

開発者は 4 つのコアアクションを使用してレコメンデーションをトリアージできます：

| アクション              | コントロール          | 効果                                                                                                                                                                                                                                        |
| ----------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Accept**              | CircleCheck ボタン    | レコメンデーションを `Accepted` としてマークし、直ちにバックグラウンドの `CreatePlan` [ジョブ](04_Jobs.md)（[プロンプトウェア](../02_Concepts/02_Promptwares.md) を参照）を開始して、[計画](03_Plans.md) に新しい実装ドラフトを生成します。 |
| **Accept with Notes**   | チェックボタン        | `RecommendationNoteDialog` を開き、開発者が特定の制約や要件を追加できるようにします。エージェントは元のレコメンデーションと操作者のメモの両方を受け取ります。                                                                               |
| **Decline**             | X ボタン              | オプションの却下理由メモとともにレコメンデーションを `Declined` としてマークし、保留中キューから削除します。                                                                                                                                |
| **Create GitHub Issue** | GitHub アイコンボタン | `CreateIssueDialog` を開き、プロジェクトリポジトリ内の [GitHub CLI](https://cli.github.com)（`gh`）を介してレコメンデーションを直接 [GitHub](https://github.com) issue として提出します。レコメンデーションは `Pending` のまま残ります。    |

アクションが完了すると、Tendril はキュー内の次のレコメンデーションに自動的に進み、提案された改善の迅速なレビューを可能にします。
