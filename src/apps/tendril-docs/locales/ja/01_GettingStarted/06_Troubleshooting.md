# トラブルシューティング

一般的な設定、エージェント、計画、データベースの問題を診断して解決します。

## インストールと環境

| 症状                                 | 対処方法                                                                                                                                                                                                                                      |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TENDRIL_HOME` が見つからない        | 環境変数を設定してターミナルを再起動するか、パスを `~/.tendril_location` に記述します。どちらも指定されていない場合、Tendril はデフォルトで `~/.tendril` を使用します。                                                                       |
| `config.yaml` が見つからない         | ファイルは `$TENDRIL_HOME/config.yaml` に存在し、`tendril-config.yaml` ではなく完全にその名前である必要があります。`tendril doctor` で想定されるパスを確認できます。                                                                          |
| `gh` が認証されていない              | [GitHub CLI](https://cli.github.com/) の認証を実行します：`gh auth login` を実行後、`gh auth status` で確認します。                                                                                                                           |
| `git` が見つからない                 | [Git](https://git-scm.com/) をインストールし、`PATH` に含まれていることを確認します。                                                                                                                                                         |
| ビルド後に `tendril` が認識されない  | `cargo build --release` はバイナリを `target/release/tendril` に出力します。これを `PATH` に追加するか、`cargo install --path src/crates/tendril-cli` を実行してください。                                                                    |
| アプリは起動するが何も読み込まれない | デスクトップアプリは `tendril run` デーモンを監視します。パッケージ化されたビルドにサイドカーバイナリが含まれていない場合、通信対象のデーモンが存在しません。パッケージ手順については [インストール](02_Installation.md) を参照してください。 |

## 計画

| 症状                                                   | 対処方法                                                                                                                                                                    |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 計画が `Draft` のまま進まない                          | `tendril plan get <id>` でリポジトリが紐付けられているか確認し、`config.yaml` にプロジェクト定義が存在するか確認します。                                                    |
| 計画フォルダが不完全に見える、または読み込みに失敗する | `tendril plan validate <id>` を実行して問題を調査します（無効な `plan.yaml`、欠落した `Revisions/`、空のタイトル、スキーマバージョンの不一致など）。                        |
| 計画のスキーマが古い                                   | `tendril plan doctor --fix` を実行して計画フォルダを最新スキーマに移行します。孤立した空の計画の抜け殻を削除するには、`tendril plan doctor --prune-husks` を実行します。    |
| 計画にリポジトリが設定されていない                     | `tendril plan add-repo <id> <path>` を実行します。                                                                                                                          |
| 実行失敗後に古いワークツリーが残っている               | 終了した計画のワークツリーを削除するには `tendril plan cleanup <id>` を実行します。終了していない計画の場合は `--force` を指定します：`tendril plan cleanup <id> --force`。 |

## 実行とエージェント

| 症状                           | 対処方法                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| エージェントにアクセスできない | `config.yaml` の `codingAgent` を確認し、クリーンなシェルでエージェントの CLI を直接実行します。Tendril は子プロセスとしてエージェントを実行します。`claude`、`codex`、`copilot`、`gemini`、`opencode`、`antigravity`、または `cursor` が無人で実行できない場合、バックグラウンドジョブが停止します。`apple` の場合は、`fm available` を確認し、`fm serve` がアクティブであることを確認してください。 |
| 実行が即座に失敗する           | `$TENDRIL_HOME/Jobs/{jobId}-{planId}-{promptware}/` にあるジョブログを確認します。一般的な原因としては、リポジトリコンテキストの欠落や、[プロンプトウェア](../02_Concepts/02_Promptwares.md) でのツール権限の不足が挙げられます。                                                                                                                                                                     |
| 検証が失敗し続ける             | 計画の分離されたワークツリー（`$TENDRIL_HOME/Plans/{id}-{name}/Worktrees/{repo}`）内で検証コマンドを手動で実行します。通常コマンド自体は正しく、ワークツリーでセットアップ手順が不足しています。詳細は [コードベースのオンボーディング](03_Onboarding.md) を参照してください。                                                                                                                        |
| ジョブが開始されない           | `tendril job queue` を実行してディスパッチ順序と並行制限（`config.yaml` の `maxConcurrentJobs`）を確認します。キューに入っているジョブやブロックされているジョブは `tendril job force-start <id>` で強制開始でき、停止したジョブは `tendril job stop-all` で停止できます。[ライフサイクルとジョブ](../02_Concepts/03_Lifecycle.md) を参照してください。                                               |
| 音声入力が利用不可と表示される | macOS の場合、システム設定 → プライバシーとセキュリティ → マイク でマイクのアクセス許可を付与し、デスクトップアプリを再起動してください。                                                                                                                                                                                                                                                             |

## データベース

Tendril は `$TENDRIL_HOME/tendril.db` で [SQLite](https://www.sqlite.org) データベースを管理します。デーモン起動時にマイグレーションが自動的に実行されますが、専用のデータベースコマンドも提供されています：

```bash
# 現在のデータベーススキーマバージョンを確認
tendril db version

# 保留中のマイグレーションを適用
tendril db migrate

# データベースの整合性を検証
tendril db integrity

# 未使用のディスク領域を回収
tendril db vacuum

# データベースをリセット（確認プロンプトあり）
tendril db reset
```

| 症状                                 | 対処方法                                                                                                                                                                                                                                |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| データベースが正常かどうかわからない | `tendril doctor`（接続性を確認）または `tendril db integrity` を実行して、内部の SQLite 整合性を確認します。                                                                                                                            |
| データベースがロックされている       | 別のプロセスが排他ロックを保持しています。同時に実行できるデーモンは 1 つだけです。手動で `tendril run` や `tendril serve` を実行する前に、デスクトップアプリを終了してください。                                                       |
| データベースが破損している           | アプリとデーモンを停止し、`tendril db reset` を実行します（または `$TENDRIL_HOME/tendril.db` と `-wal`、`-shm` ファイルを削除します）。ディスク上の `$TENDRIL_HOME/Plans/` にある計画の Markdown ファイルは完全にそのまま保持されます。 |

> [!TIP]
> [Discord](https://discord.gg/FHgxkDga3y) や GitHub でサポートを求める際は、`tendril report-bug <plan-id>` を使用して完全な診断ログをまとめてください。[ヘルプとサポート](05_GettingHelp.md) を参照してください。
