# コンセプト

Tendril は簡潔な概念モデルを備えており、デスクトップアプリと CLI のすべての要素は、これら 3 つのコアプリミティブのいずれかにマッピングされます：

- [計画](01_Plans.md) — 基本的な作業単位。計画はディスク上の透過的なフォルダであり、ステートマシン、不変の改訂セット、インライン注釈、および自動検証です。
- [プロンプトウェア](02_Promptwares.md) — 計画をある状態から次の状態へと進める単一目的のワークフローエージェント。それぞれが独自のシステムプロンプト、限定されたツール権限、および長期記憶を持っています。
- [ライフサイクルとジョブ](03_Lifecycle.md) — 計画に対する 1 つのプロンプトウェアの 1 回の実行がジョブを構成します：ステータス、テレメトリ、分離された Git ワークツリー、コスト追跡、および作業をレビューに進めるかどうかを決定する品質ゲート。

まだループを実行していない場合は、[チュートリアル](../01_GettingStarted/04_Tutorial.md) でこれらのプリミティブが動作する様子を確認できます。また、リポジトリを並行ワークツリーに対応させる準備については [コードベースのオンボーディング](../01_GettingStarted/03_Onboarding.md) を確認してください。
