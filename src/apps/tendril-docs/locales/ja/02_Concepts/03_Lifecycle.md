# ライフサイクルとジョブ

Tendril がユーザーに代わってアクションを実行するたびに、**ジョブ (job)** が作成されます。これは、1 つの [計画](01_Plans.md) に対して単一の [ワークフローエージェント（プロンプトウェア）](02_Promptwares.md) を 1 回実行することを意味します。ジョブを通じて計画はそのライフサイクルを進み、デスクトップアプリや CLI でリアルタイムにその様子を観察できます。

## ジョブのステータス

| ステータス    | 意味                                                                 |
| ------------- | -------------------------------------------------------------------- |
| **Pending**   | 作成済みですが、まだキューに受け入れられていません。                 |
| **Queued**    | 利用可能な並行スロットを待機しています。                             |
| **Running**   | コーディングエージェントプロセスがアクティブに実行中です。           |
| **Completed** | 正常に完了し、必要なすべてのゲートに合格しました。                   |
| **Failed**    | エージェントがエラーを起こしたか、必要な検証チェックに失敗しました。 |
| **Timeout**   | 設定された実行時間制限を超過したため、終了されました。               |
| **Stopped**   | ユーザーの操作によって停止されました。                               |
| **Blocked**   | 依存ジョブ、認証情報、または判断を待機しているため、進行できません。 |

## 実行ループ

1. **キュー (Queue)** — ジョブが作成され、現在実行中のタスクの後ろのキューに入れられます。
2. **準備 (Prepare)** — コードを変更するプロンプトウェア（[ExecutePlan](02_Promptwares.md)、[RetryPlan](02_Promptwares.md)）の場合、Tendril は計画の `Worktrees/{repo-name}/` フォルダの下にリポジトリごとの分離された [Git ワークツリー](https://git-scm.com/docs/git-worktree) をプロビジョニングします。プライマリの作業チェックアウトに触れたりロックしたりすることはありません。
3. **実装 (Implement)** — ワークフローエージェントが計画のフェーズに沿って作業を進め、インクリメンタルなコミットを作成します。
4. **検証 (Verify)** — 設定された各検証ゲートがワークツリー内で実行され、その結果が記録されます。
5. **レポート (Report)** — 出力ログ、トークンコスト、および更新された計画状態がディスクに保存され、デーモンに報告されます。

ジョブを停止すると、計画はジョブ開始前の状態に戻りますが、部分的な進行状況を確認できるようにワークツリーの状態は保持されます。完全な状態テーブルについては [計画](01_Plans.md) を参照してください。

## 検証 (Verifications)

検証とは、`plan.yaml` に記録される自動品質ゲートです。各チェックは `Pass`、`Fail`、または `Skipped` の結果を生成し、計画の `Verification/` フォルダ内に詳細なレポートを出力します。どのチェックが実行されるかは、計画が変更するファイルによって異なります：

| 検証            | チェック内容                                                                         |
| --------------- | ------------------------------------------------------------------------------------ |
| **NpmBuild**    | pnpm / npm ワークスペースがクリーンにビルドされるか。                                |
| **NpmLint**     | TypeScript / JavaScript パッケージの lint とフォーマットが合格するか。               |
| **NpmTest**     | 自動テストスイート（Vitest、Jest など）が合格するか。                                |
| **RustBuild**   | Cargo パッケージがコンパイラエラーなしでコンパイルされるか。                         |
| **RustClippy**  | Clippy linter が警告やエラーを報告しないか。                                         |
| **RustFormat**  | `cargo fmt --check` が一貫したフォーマットを報告するか。                             |
| **RustTest**    | Rust の単体テストおよび統合テストスイートが合格するか。                              |
| **Screenshots** | UI の変更に対して視覚的な証拠がキャプチャされたか。                                  |
| **CheckResult** | 計画の基準が満たされているかについてのエージェント自身によるエンドツーエンドの確認。 |

計画に適用されない検証は、暗黙的に省略されるのではなく `Skipped` としてマークされ、明確な監査証跡が確保されます。計画は、必要な検証に合格した場合にのみ **Review** に到達します。検証が失敗した場合、計画は **Failed** に入り、[RetryPlan](02_Promptwares.md) が正確なエラー出力と現在の差分をコンテキストとして受け取り、修正を再試行できます。

> [!TIP]
> 検証が失敗した場合は、`Verification/` のレポートを確認し、計画のワークツリー内でコマンドを直接テストしてください。通常チェック自体は正しく、ワークツリーに依存関係やビルド成果物が不足しているだけの場合があります — [コードベースのオンボーディング](../01_GettingStarted/03_Onboarding.md) を参照してください。

## 並行性とワークツリー

複数のジョブを同時に実行でき、[~/.tendril/config.yaml](../03_Configuration/01_Setup.md) の `maxConcurrentJobs`（デフォルト `20`）によって制御されます：

```yaml
maxConcurrentJobs: 4
```

実行中の各計画は専用の [Git ワークツリー](https://git-scm.com/docs/git-worktree) 内で動作するため、同じリポジトリに対する並行ジョブが衝突することはありません。ただし、並行実行では CPU、メモリ、およびコーディングエージェントの API レート制限が共有されるため、ワークステーションに合わせて `maxConcurrentJobs` を調整してください。

## コスト追跡

毎回の実行で、消費されたトークンと推定金額コストが記録されます。永続的な監査ログは計画の `costs.csv` であり、実行ごとに 1 行ずつ追加されます：

```csv
Promptware,Tokens,Cost,Model,CostSource,Agent
ExecutePlan,148213,1.9042,claude-opus-5,api,claude
```

エージェントが無制限のサブスクリプション（または Apple Foundation Models などのローカルモデル）で実行される場合、`Cost` フィールドはゼロを記録するのではなく空のままになり、金額を捏造することなくトークンメトリクスを保持します。

## ジョブの管理と検査

デスクトップアプリは、デーモンの WebSocket ストリームを介してリアルタイムのジョブステータスとストリーミングターミナル出力を表示します。CLI でも同等の操作が可能です：

```bash
# すべてのアクティブおよび最近のジョブを一覧表示
tendril job list

# ステータスでジョブをフィルタリング
tendril job list --status Running
tendril job list --status Failed

# ディスパッチキューの順序と利用可能なスロットを確認
tendril job queue

# キューに入っているジョブやブロックされているジョブを即座に実行するよう昇格
tendril job force-start <job-id>

# 実行中のジョブをキャンセル
tendril job cancel <job-id> -m "Stopping for review"

# 実行中、キュー待機中、ブロック中のすべてのジョブを停止
tendril job stop-all

# 完了または失敗したジョブをデータベースから削除
tendril job clear --completed
tendril job clear --failed
```

生のシステムプロンプト、ツール実行トレース、エージェントの文字起こし記録を含む、毎回の実行の完全なログとトランスクリプトは、`$TENDRIL_HOME/Jobs/{jobId}-{planId}-{promptware}/` に恒久的に保存されます。
