# 改进建议

建议应用是 Tendril 的分类处理中心，用于处理在计划执行期间发现的由 AI 建议的代码库优化、测试覆盖率补充、架构整洁性改进和技术债务项。

## 来源与准入条件

随着 [编程智能体](../06_CodingAgents/_Index.md) 对计划进行分析、执行和验证，它们会发现相关的改进点（例如未测试的边界情况、已弃用的依赖项、重构机会或性能瓶颈）。

为了保持建议的可操作性并避免过早推进工作：

- 只有源自 **Completed**（已完成）状态计划的建议才会出现在建议应用中（请参阅 [任务生命周期](../02_Concepts/03_Lifecycle.md)）。
- 源自失败或正在执行的计划的建议将始终与源计划保持关联，直到该计划执行成功。

## 建议队列

侧边栏展示所有待处理的建议：

- **源计划标签** — 显示来源计划编号（例如 `#14`）。
- **标题** — 提议改进的简要说明。
- **项目徽章** — 标明建议针对哪个项目仓库（在 [项目设置](../03_Configuration/02_Projects.md) 中配置）。
- **影响徽章** — 按颜色区分的紧迫性与价值评估：
  - `High`（绿色）— 关键修复、重大重构或不可或缺的测试缺失。
  - `Medium`（黄色）— 清理、可维护性提升或非阻塞性改进。
  - `Low`（中性灰色）— 次要细节修饰或外观优化。

## 详情视图与分类决策操作

选择某条建议后，将显示其完整的技术论据、影响评估，以及在 [计划](03_Plans.md) 中打开原始 **源计划** 的链接。

开发者可以使用四个核心操作对建议进行分类决策：

| 操作                    | 控件             | 效果                                                                                                                                                                          |
| ----------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Accept**              | CircleCheck 按钮 | 将建议标记为 `Accepted`，并立即启动后台 `CreatePlan` [任务](04_Jobs.md)（请参阅 [Promptware](../02_Concepts/02_Promptwares.md)），在 [计划](03_Plans.md) 中搭建新的实现草案。 |
| **Accept with Notes**   | 勾选按钮         | 打开 `RecommendationNoteDialog`，允许开发者添加特定约束或要求。智能体将同时接收到原始建议与操作者的批注。                                                                     |
| **Decline**             | X 按钮           | 将建议标记为 `Declined`（附带可选的拒绝说明），并将其从待处理队列中移除。                                                                                                     |
| **Create GitHub Issue** | GitHub 图标按钮  | 打开 `CreateIssueDialog`，通过项目仓库中的 [GitHub CLI](https://cli.github.com) (`gh`) 将建议直接提交为 [GitHub](https://github.com) Issue。该建议保持为 `Pending` 状态。     |

一旦操作完成，Tendril 会自动前进至队列中的下一条建议，以便快速审查所有提议的改进。
